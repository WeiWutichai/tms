# Runbook — นับ ticket support รายเดือนต่อ tenant (เกณฑ์ผ่านเฟส 1 ข้อ (ค))

> P1-ST6-T03 · **[DECISION — lead 27 พ.ย. 2569, ย้อนได้]** · เกณฑ์ `docs/02` §7 เฟส 1 **(ค) ticket ต่อ tenant ต่อเดือน ≤ 2** · ช่องทางจริง (อีเมล support / LINE OA ของ Innovera) = X-04 ยังไม่ได้รับ — ขั้นตอนนี้ใช้ได้ทันทีที่ตั้งค่า

## 1. ที่มาของ ticket

| ช่องทาง | ผู้ใช้ส่งจาก | สิ่งที่แนบมาให้อัตโนมัติ |
|---|---|---|
| อีเมล support | แอป: ปุ่มคู่มือ (ไอคอนหนังสือ แถบบน) → **ติดต่อทีมงานทางอีเมล** | หัวเรื่อง `[TMS-SUPPORT] ติดต่อทีมงาน · รหัสบริษัท <tenant id>` · เนื้อความ: รหัสบริษัท + หน้าที่เปิดอยู่ (ชื่อหน้า + path ไม่รวม query) |
| LINE OA | แอป: เมนูเดียวกัน → **ติดต่อทีมงานทาง LINE** | ข้อความร่างบรรทัดแรก = หัวเรื่องเดียวกัน ตามด้วยรหัสบริษัท + หน้า |
| อื่น ๆ (โทร, อีเมลส่งตรง, LINE ที่ไม่ได้ผ่านปุ่ม) | — | ไม่มี — ผู้รับต้องบันทึกรหัสบริษัทเอง (ข้อ 3) |

- รหัสบริษัท = ค่า `tenant.id` ของ `GET /v1/me` รูป `ten_<uuid ไม่มีขีด 32 ตัว>` — ตัด `ten_` แล้วใส่ขีดกลับ (8-4-4-4-12) = UUID ของ tenant ในฐานข้อมูล/Platform Console · ไม่มีข้อมูลส่วนบุคคลอื่นในข้อความที่ระบบร่าง
- ป้าย `[TMS-SUPPORT]` เป็นค่าคงที่ในโค้ด (`apps/web/src/help/contact.ts` `SUPPORT_TAG`) — เปลี่ยนต้องแก้ runbook นี้ด้วย

## 2. ตั้งค่า (ครั้งเดียว ก่อน go-live)

1. ได้อีเมล support และ LINE OA จาก PO (X-04)
2. ตั้งตอน build image เว็บ: `--build-arg VITE_SUPPORT_EMAIL=<อีเมล> --build-arg VITE_SUPPORT_LINE_OA=@<id>` (`infra/deploy/web.Dockerfile`) — ไม่ตั้ง = ปุ่มติดต่อในแอปปิดพร้อมข้อความ
3. กล่องอีเมล support: ตั้ง filter หัวเรื่องมี `[TMS-SUPPORT]` → ป้าย (label) `tms-support` · ตั้ง filter ย่อยต่อ tenant ตามรหัสบริษัท ถ้ากล่องรองรับ
4. LINE OA: ตั้งแท็ก (tag) แชท `tms-support` และใส่โน้ตรหัสบริษัทในโปรไฟล์ผู้ติดต่อเมื่อเปิดแชทครั้งแรก
5. ตาราง ticket (spreadsheet ภายใน Innovera — ไม่เก็บใน repo): คอลัมน์ `วันที่รับ · ช่องทาง · รหัสบริษัท · หน้า · ประเภท (คำถามใช้งาน / ข้อผิดพลาด / ขอฟีเจอร์ / บัญชีและการชำระ) · ซ้ำกับ ticket ไหน · ปิดเมื่อ`

## 3. ทุกวัน (ผู้รับ ticket)

1. ทุกข้อความใหม่ในป้าย/แท็ก `tms-support` → เพิ่ม 1 แถวในตาราง ticket
2. ข้อความที่ไม่ได้ผ่านปุ่ม (ไม่มีรหัสบริษัท) → ถามชื่อบริษัท แล้วหา id ของ tenant จากรายชื่อลูกค้าใน Platform Console → กรอกรหัสบริษัทในตาราง (หาไม่ได้ = กรอกชื่อบริษัทไว้ก่อน)
3. ข้อความต่อเนื่องในเรื่องเดิม (ตอบกลับในเธรดเดียวกัน) **ไม่นับ** เป็น ticket ใหม่ · เรื่องใหม่จากบริษัทเดิม = ticket ใหม่
4. ไม่นับ: ข้อความทดสอบของทีมเอง, tenant ของทีมเอง/เดโม, แถว sandbox ของบริษัท (ตาราง `tenant` คอลัมน์ `mode = 'test'` — ST7-T09 ไม่ใช่บริษัทแยก), spam

## 4. ทุกเดือน (วันทำการแรกของเดือน — เจ้าของ: PO หรือผู้ที่ PO มอบหมาย)

1. กรองตาราง ticket ด้วย `วันที่รับ` ของเดือนที่แล้ว (เวลาไทย)
2. นับจำนวน ticket ต่อ `รหัสบริษัท` · นับจำนวน tenant ที่ใช้งานในเดือนนั้น (สถานะ trial/active ใน Platform Console)
3. คำนวณ: **ticket ต่อ tenant = ticket ทั้งหมด ÷ tenant ที่ใช้งาน** และรายชื่อ tenant ที่มี ticket > 2
4. บันทึกลง `PROGRESS.md` หัวข้อบันทึกรายวันของวันนั้น บรรทัดเดียว:
   `- **ticket support <เดือน ปี>:** <ทั้งหมด> ticket / <n> tenant = <ค่าเฉลี่ย> ต่อ tenant (เกณฑ์ (ค) ≤ 2) · tenant ที่เกิน: <รหัส…> · ประเภทที่มากสุด: <…>`
5. ประเภทที่มากสุด → เปิดงานแก้บทความ help center หรือ UI (ข้อความ error ที่ไม่ชัด) ใน backlog ถัดไป

## 5. ข้อห้าม

- ไม่คัดลอกเนื้อหา ticket / ข้อมูลส่วนบุคคลของผู้ติดต่อลง repo หรือ PROGRESS — บันทึกเฉพาะตัวเลขและรหัสบริษัท
- ไม่ส่งข้อมูลลูกค้าไปเครื่องมือภายนอกที่ยังไม่ผ่านการตรวจ PDPA (`plan/legal/`)
