# TMS Design Brief สำหรับ Claude Design

Oct 14, 2026 · @wei

ระบบ TMS เป็นเครื่องมือทำงานของบัญชีและฝ่ายขนส่งที่ใช้ทั้งวัน บุคลิกจึงเป็น **ทางการ นิ่ง เชื่อถือได้** แบบระบบการเงิน ไม่ใช่สตาร์ทอัพสีสด: สีหลักน้ำเงินกรมท่า, neutral โทนเทาเย็น, accent สีอำพันใช้เฉพาะปุ่มหลักและสิ่งที่ต้องตัดสินใจ, ตัวอักษร IBM Plex Sans Thai บน UI และ Sarabun บนเอกสารพิมพ์

## 1. ทิศทางและบุคลิก

**ผู้ใช้หลัก** — ฝ่ายวางแผนรถ (หน้าจอหนาแน่น ใช้ทั้งวัน), ฝ่ายบัญชี (ตัวเลขต้องอ่านง่าย เทียบได้), ผู้บริหาร (dashboard สรุป), ทีม Innovera (admin portal) — ทั้งหมดใช้บนเดสก์ท็อป/แล็ปท็อป ขนาดจอ 1366–1920 เป็นหลัก

**บุคลิก 4 คำ:** ทางการ · แม่นยำ · สงบ · ชัดเจน

**อ้างอิงความรู้สึก:** ระบบ core banking / โปรแกรมบัญชียุคใหม่ (เช่น Xero, Stripe Dashboard ในโทนเข้มขึ้น) — ไม่ใช่แอปเรียกรถหรือ e-commerce

**ต้องหลีกเลี่ยง**

- gradient, เงาหนัก, การ์ดมุมโค้งใหญ่, สีสดหลายสีในหน้าเดียว
- ไอคอนแบบการ์ตูน, ภาพประกอบ, emoji ใน UI
- ตัวอักษรไทยขนาดเล็กกว่า 14px ในตาราง, ช่องตารางแคบจนภาษาไทยตัดคำ
- สีเป็นตัวบอกสถานะเพียงอย่างเดียว (ต้องมีข้อความสถานะเสมอ เพื่อผู้ที่ตาบอดสีและการพิมพ์ขาวดำ)
- dark mode ไม่ทำในเฟสแรก (เอกสารบัญชีพิมพ์ขาวดำ)

## 2. ระบบสีทางการ

ใช้ 1 primary + 1 accent + neutral 9 ระดับ + semantic 4 สี ทุกคู่ข้อความ/พื้นหลังผ่าน WCAG AA (4.5:1) อย่างน้อย

**Primary — Navy (ความน่าเชื่อถือ ใช้กับ header, sidebar, ลิงก์, ปุ่มรอง)**

| Token | Hex | ใช้กับ |
| --- | --- | --- |
| `primary-900` | `#0B1F3A` | sidebar, top bar, หัวเอกสารพิมพ์ |
| `primary-700` | `#163A66` | ปุ่มรอง (outline/text), ลิงก์, heading เน้น |
| `primary-500` | `#2457A0` | hover ของลิงก์, focus ring, กราฟเส้นหลัก |
| `primary-100` | `#E3EAF5` | แถวตารางที่เลือก, พื้นหลัง tab ที่ active |
| `primary-050` | `#F2F5FA` | พื้นหลัง section ที่ต้องแยกจากพื้นขาว |

**Accent — Amber (การกระทำหลักและสิ่งที่รอการตัดสินใจ ใช้ไม่เกิน 1 จุดต่อหน้าจอ)**

| Token | Hex | ใช้กับ |
| --- | --- | --- |
| `accent-600` | `#B8690F` | ปุ่มหลัก (primary CTA) ข้อความขาว |
| `accent-500` | `#D9821A` | hover ของปุ่มหลัก |
| `accent-100` | `#FBEFDD` | พื้นหลัง badge "รอดำเนินการ" |

**Neutral — Cool gray (พื้นผิว ข้อความ เส้น)**

| Token | Hex | ใช้กับ |
| --- | --- | --- |
| `gray-900` | `#111827` | ข้อความหลัก |
| `gray-700` | `#374151` | ข้อความรอง, label |
| `gray-500` | `#6B7280` | ข้อความช่วย, placeholder, caption |
| `gray-300` | `#D1D5DB` | เส้นขอบ input, เส้นตาราง |
| `gray-200` | `#E5E7EB` | เส้นแบ่ง section |
| `gray-100` | `#F3F4F6` | หัวตาราง, พื้นหลัง input disabled |
| `gray-050` | `#F9FAFB` | พื้นหลังหน้า (canvas) |
| `white` | `#FFFFFF` | การ์ด, ตาราง, modal |

**Semantic (ใช้คู่กับข้อความเสมอ)**

| ความหมาย | สีข้อความ | พื้นหลัง badge | ขอบ |
| --- | --- | --- | --- |
| สำเร็จ / ตรงกัน | `#166534` | `#DCFCE7` | `#86EFAC` |
| เตือน / รอคน | `#92400E` | `#FEF3C7` | `#FCD34D` |
| ผิดพลาด / ไม่ตรง | `#991B1B` | `#FEE2E2` | `#FCA5A5` |
| ข้อมูล / กำลังทำ | `#1E40AF` | `#DBEAFE` | `#93C5FD` |
| ปิด / ยกเลิก | `#374151` | `#F3F4F6` | `#D1D5DB` |

**สีสถานะเอกสาร (ผูกกับ state machine ในเอกสารเทคนิค)**

| สถานะ | semantic |
| --- | --- |
| SO: `RECEIVED`, DO: `DRAFT`, Invoice: `DRAFT`, `READY` | ข้อมูล |
| SO: `ROUTE_PENDING`, `CUSTOMER_UNMAPPED`; Invoice: `RETRY_WAIT`, `APPROVAL_PENDING`, `EDIT_PENDING` | เตือน |
| Invoice: `REJECTED`, `FAILED`, `MISMATCH`; DO: `FAILED` | ผิดพลาด |
| SO: `PLANNED`, `DELIVERED`; DO: `DELIVERED`, `BILLED`; Invoice: `ACCEPTED`, `POSTED` | สำเร็จ |
| `CANCELLED`, `CLOSED` | ปิด |

**กฎการใช้สี**

1. ปุ่ม accent มีได้ 1 ปุ่มต่อหน้าจอ ("บันทึก", "ส่งเข้า KRS", "อนุมัติ") ปุ่มอื่นเป็น navy outline หรือ text
2. สีแดงใช้กับ error และปุ่มทำลาย (ลบ/ยกเลิก) เท่านั้น ไม่ใช้เน้นตัวเลขติดลบ (ใช้วงเล็บหรือเครื่องหมายลบ + gray-900)
3. กราฟใช้ `primary-500`, `primary-900`, `gray-500`, `accent-500` ตามลำดับ ไม่เกิน 4 series
4. เอกสารพิมพ์ (DO, Invoice) ขาวดำล้วน ยกเว้นโลโก้และเส้นหัวเอกสาร `primary-900`

## 3. ตัวอักษรและ type scale

UI ใช้ **IBM Plex Sans Thai** (ไทย-อังกฤษออกแบบคู่กัน ตัวเลขชัด ดูทางการแบบองค์กร) เอกสารพิมพ์ใช้ **Sarabun** (ฟอนต์มาตรฐานราชการไทย คุ้นตาฝ่ายบัญชี) ตัวเลขและรหัสเอกสารใช้ **IBM Plex Mono** ทั้งสองฟอนต์เป็น Google Fonts ฟรีเชิงพาณิชย์

| ฟอนต์ | ใช้กับ | เหตุผล |
| --- | --- | --- |
| IBM Plex Sans Thai | UI ทั้งหมด | สระ-วรรณยุกต์ไทยไม่ชนบรรทัด, มี 7 น้ำหนัก, ภาษาอังกฤษไม่โดดจากไทย |
| IBM Plex Mono | เลข SO/DO/Invoice, ทะเบียนรถ, ยอดเงินในตาราง, JSON ใน log | ตัวเลขกว้างเท่ากัน เทียบคอลัมน์ได้ด้วยตา |
| Sarabun | DO, Invoice, รายงานพิมพ์, PDF | มาตรฐานเอกสารทางการไทย อ่านง่ายบนกระดาษ |

**Type scale (UI)** — base 14px, line-height ไทย 1.6 ขึ้นไป

| ชื่อ | ขนาด / น้ำหนัก | line-height | ใช้กับ |
| --- | --- | --- | --- |
| Display | 28px / 600 | 1.4 | ชื่อหน้า (ใช้น้อย) |
| H1 | 22px / 600 | 1.4 | หัวข้อหน้า |
| H2 | 18px / 600 | 1.5 | หัว section, ชื่อการ์ด |
| H3 | 16px / 600 | 1.5 | หัวตาราง, หัว modal |
| Body | 14px / 400 | 1.6 | ข้อความทั่วไป, เซลล์ตาราง |
| Body strong | 14px / 600 | 1.6 | ค่าที่ต้องเด่น เช่น ยอดรวม |
| Caption | 12px / 400 | 1.6 | คำอธิบาย, timestamp — **ห้ามใช้กับภาษาไทยที่ต้องอ่านจริงจัง** |
| Mono | 13px / 400 | 1.6 | รหัสเอกสาร, ตัวเลขในตาราง |

**Type scale (เอกสารพิมพ์ A4)** — Sarabun 16pt body, 14pt ตาราง, 20pt ชื่อเอกสาร, 12pt หมายเหตุท้ายใบ

**กฎ**

- ตัวเลขเงินชิดขวา ใช้ทศนิยม 2 ตำแหน่งและเครื่องหมายคั่นหลักพันเสมอ (2,054,000.00)
- วันที่ในหน้าจอ: `14 ต.ค. 2569` (พ.ศ. ตามบัญชีไทย) และโชว์ ค.ศ. ในเอกสารที่ส่ง API; ตั้งค่าเลือกได้ต่อ tenant
- ไม่ใช้ตัวพิมพ์ใหญ่ทั้งคำ (ALL CAPS) ในภาษาอังกฤษ ยกเว้นรหัสสถานะในโค้ด
- ไม่ใช้ตัวเอียงกับภาษาไทย

## 4. Layout, spacing และ component หลัก

โครงหน้าแบบ sidebar ซ้าย + เนื้อหาขวาแบบตารางหนาแน่น ใช้ spacing ฐาน 4px, มุมโค้ง 4px, ไม่มีเงานอกจาก modal และ dropdown

**โครงหน้า**

| ส่วน | ขนาด | รายละเอียด |
| --- | --- | --- |
| Sidebar | 240px (ย่อเหลือ 56px) | พื้น `primary-900`, ข้อความขาว 85%, เมนูที่ active มีแถบ accent ซ้าย 3px, badge จำนวนงานค้างสีอำพัน |
| Top bar | 56px | ชื่อ tenant, ค้นหาเลขเอกสาร (global search), สถานะเชื่อม KRS (จุดเขียว/แดง + ข้อความ), ผู้ใช้ |
| Content | max 1440px, padding 24px | พื้น `gray-050`, การ์ดสีขาวขอบ `gray-200` |
| Side panel | 480px เลื่อนจากขวา | รายละเอียดเอกสารโดยไม่ออกจากตาราง |

**Spacing scale:** 4 · 8 · 12 · 16 · 24 · 32 · 48 — ระยะในตาราง 12px แนวตั้ง / 16px แนวนอน, ระหว่างการ์ด 24px

**Component ที่ต้องกำหนดใน design system**

| Component | ข้อกำหนด |
| --- | --- |
| Data table | หัวตาราง `gray-100` ตรึงบน, แถวสูง 44px, เส้น `gray-200`, hover `gray-050`, เลือกแล้ว `primary-100`, คอลัมน์ตัวเลขชิดขวา mono, sort/filter/column picker, แถวคลิกเปิด side panel |
| Status badge | ข้อความ + สี semantic, สูง 24px, มุม 4px, ไม่มีไอคอน |
| Button | Primary (accent เต็ม), Secondary (navy outline), Tertiary (text), Destructive (แดง outline); สูง 36px; ปุ่ม primary 1 ปุ่มต่อหน้า |
| Form input | สูง 36px, ขอบ `gray-300`, focus ring `primary-500` 2px, label บนช่อง, error แดงใต้ช่องพร้อมข้อความ |
| Compare view (TMS vs KRS) | ตารางสองคอลัมน์ค่าซ้าย-ขวา แถวที่ต่าง highlight `#FEE2E2` + ข้อความ "ต่าง" ไม่ใช้สีอย่างเดียว |
| Diff view (revision) | เพิ่ม = พื้นเขียวอ่อน, ลบ = แดงอ่อน + ขีดฆ่า, แก้ = เหลืองอ่อน |
| Timeline (log การส่ง) | เส้นแนวตั้ง, จุดสี semantic ตาม status code, เวลา mono, ขยายดู JSON |
| Empty state | ข้อความ 1 บรรทัด + ปุ่มรอง ไม่มีภาพประกอบ |
| Toast / Alert | แถบบนขวา, สี semantic, ปิดเอง 5 วินาที ยกเว้น error |
| Approval dialog | modal 560px, แสดง diff, ช่องเหตุผลบังคับ, ปุ่มอนุมัติ (accent) / ไม่อนุมัติ (outline) |

**เอกสารพิมพ์ (DO / Invoice)** — A4 แนวตั้ง, หัวเอกสาร: โลโก้ซ้าย ชื่อเอกสารขวา 20pt, กล่องข้อมูลคู่ค้าและเลขเอกสารใต้หัว, ตารางรายการเส้นบางสีดำ, ยอดรวมกล่องขวาล่าง, ช่องลายเซ็น 3 ช่องท้ายใบ, เลขหน้า "1/2"

## 5. หน้าจอที่ให้ออกแบบก่อน และ prompt สำหรับ Claude Design

เริ่มจาก design system แล้วออกแบบ 4 หน้าที่คนใช้ทั้งวัน ตามลำดับความถี่ หน้าอื่นใช้ component เดียวกันต่อได้

| ลำดับ | หน้าจอ | สิ่งที่ต้องเห็นในแบบ |
| --- | --- | --- |
| 0 | Design system | palette, type scale, ปุ่ม 4 แบบ, input, badge ทุกสถานะ, data table, side panel |
| 1 | ใบ SO รอกำหนดเส้นทาง | ตารางกรอง + badge เหตุผล + side panel เลือกเส้นทาง/รถ |
| 2 | วางบิล | เลือกลูกค้า+ช่วงวันที่ → ติ๊ก DO → ยอดรวมสด → preview payload |
| 3 | ใบที่ไม่ตรงกับ KRS | compare view TMS vs KRS + ปุ่ม 3 ทางเลือก + approval dialog |
| 4 | Dashboard เชื่อมต่อ KRS | การ์ดตัวเลข 4 ใบ, คิว outbox, กราฟสำเร็จ 7 วัน, รายการ MISMATCH |
| 5 | เอกสารพิมพ์ Invoice | A4 Sarabun ตามข้อ 4 |

**Prompt สำหรับส่งให้ Claude Design** (คัดลอกไปใช้ได้ แนบเอกสารนี้ไปด้วย)

```markdown

บุคลิก: ทางการ แม่นยำ สงบ ชัดเจน — เหมือนระบบบัญชี/การเงิน ไม่ใช่แอปผู้บริโภค ไม่มี gradient เงาหนัก ภาพประกอบ หรือ emoji

ระบบสี (ใช้ตามนี้เท่านั้น):
- Primary navy: #0B1F3A (sidebar/top bar), #163A66 (ปุ่มรอง/ลิงก์), #2457A0 (hover/focus), #E3EAF5 (แถวที่เลือก), #F2F5FA
- Accent amber: #B8690F (ปุ่มหลัก 1 ปุ่มต่อหน้า), #D9821A (hover), #FBEFDD
- Neutral: #111827 ข้อความหลัก, #374151, #6B7280, #D1D5DB เส้นขอบ, #E5E7EB, #F3F4F6 หัวตาราง, #F9FAFB พื้นหน้า, #FFFFFF การ์ด
- Semantic badge (ข้อความ/พื้น): สำเร็จ #166534/#DCFCE7, เตือน #92400E/#FEF3C7, ผิดพลาด #991B1B/#FEE2E2, ข้อมูล #1E40AF/#DBEAFE, ปิด #374151/#F3F4F6 — badge ต้องมีข้อความเสมอ

ตัวอักษร: IBM Plex Sans Thai ทั้ง UI (body 14px/1.6, H1 22px/600, H2 18px/600, caption 12px ใช้เฉพาะ timestamp), IBM Plex Mono สำหรับเลขเอกสาร ทะเบียนรถ และยอดเงิน (ชิดขวา ทศนิยม 2 ตำแหน่ง) ภาษาไทยไม่เล็กกว่า 14px ไม่ใช้ตัวเอียง
```

## 6. รอบที่ 2: ปฏิบัติการขนส่งและ master data (ส่งหลังรอบแรกเสร็จ)

รอบแรกครอบคลุมแค่ flow KRS รอบนี้คือหน้าที่ฝ่ายวางแผนและ dispatcher ใช้ทั้งวัน ซึ่งเป็นหัวใจของ TMS ใช้ design system และ data ตัวอย่างชุดเดิม ต่อเข้า prototype เดิมผ่าน sidebar
