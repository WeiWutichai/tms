TMS API v1

เอกสาร Open API ของ TMS — endpoint ชุดเดียวกับที่เว็บของ TMS ใช้ (API-first) · เวอร์ชันพฤติกรรมล่าสุด 2026-11-18 · 378 endpoint

เริ่มที่ Quickstart (สร้าง order แรกใน Sandbox ภายใน 15 นาที) · ดาวน์โหลด Postman collection · OpenAPI · สำหรับ AI/LLM: llms.txt, llms-full.txt · ทุกหน้ามีฉบับ Markdown (<หน้า>.md)

เริ่มต้นใช้งาน

  • เริ่มต้นใช้งาน (Quickstart) — สร้างใบสั่งขนส่ง (order) แรกใน Sandbox ภายใน 15 นาที — ข้อมูล Sandbox แยกจากข้อมูลจริงทั้งหมด ลองได้ไม่ต้องกลัวพัง
  • ยืนยันตัวตน — ทุกคำขอส่ง credential ใน header Authorization: Bearer … ผ่าน HTTPS เท่านั้น — tenant (บริษัท) ระบุจาก credential ไม่มีใน URL

แนวทาง

  • แนวทางการใช้ API — มาตรฐานที่ทุก endpoint ใช้ร่วมกัน
  • Rate limit — จำกัดแบบ token bucket หลายชั้นพร้อมกัน (ค่าของแพ็กเกจมาตรฐาน — แพ็กเกจ high = 2 เท่าทุกชั้น)
  • เวอร์ชันของ API — เวอร์ชันมี 2 ชั้น: major ใน path และวันที่ของพฤติกรรมใน header X-Api-Version
  • Sandbox — Sandbox = บริษัทคู่แฝดของคุณในโหมดทดสอบ ข้อมูลแยกขาดจากข้อมูลจริง (คนละ tenant ในระบบ)
  • Webhook และการตรวจลายเซ็น — TMS ส่ง event เป็น POST JSON ไปยัง endpoint ของคุณ — รายการ event และ schema ของแต่ละตัวอยู่ที่ Webhook events
  • ทำทีละหลายรายการและงานเบื้องหลัง — POST /v1/orders:bulk body { "items": [...] } 1–200 ใบ (รูปเดียวกับ body ของ POST /v1/orders, body ≤ 1 MB) → 207 Multi-Status ผลแยกต่อรายการเรียงตาม items[] (รายการที่ไม่ผ่านไม่ย้อนรายการอื่น · ใบที่มี externalId เดิม = อัปเดตใบเดิม) · รับ Idempotency-Key · นับเป็นคำขอหนักใน rate limit
  • TypeScript SDK — @tms/sdk — client ที่มี type ครบทุก path ของ /v1 (generate จาก OpenAPI ชุดเดียวกับเอกสารนี้) ใช้ได้กับ Node.js ≥ 20, Deno, Bun และ browser/edge
  • Postman — ไฟล์ tms-api.postman_collection.json (Postman Collection v2.1) — ทุก endpoint ในเอกสารนี้ แยกโฟลเดอร์ตาม resource พร้อม body ตัวอย่างจาก schema
