# Brief สำหรับ Claude Design — TMS v2

ส่งทีละรอบตามลำดับ รอให้รอบก่อนเสร็จและตรวจแล้วค่อยส่งรอบถัดไป
(รอบ 1 เปลี่ยนโครงข้อมูล/หน้าจอ, รอบ 2 เปลี่ยนหน้าตา, รอบ 3 เพิ่มหน้าใหม่)

---

## รอบ 1 — Standalone + เชื่อม ERP ได้หลายตัว (โครงสร้าง)

ปรับ TMS v2 ให้**ใช้งานแบบ standalone เป็นค่าเริ่มต้น** และเชื่อม ERP ได้หลายตัวแบบ optional — ห้ามอ้างชื่อ KRS ใน UI หลัก (ชื่อ ERP มาจาก connector ที่เปิดในตั้งค่าเท่านั้น)

1. **แยกสถานะเอกสารออกจากสถานะซิงก์**: ใบแจ้งหนี้ใช้สถานะธุรกิจ ร่าง · ออกแล้ว (ล็อก) · ชำระบางส่วน · ชำระแล้ว · เกินกำหนด · ยกเลิก; สถานะซิงก์เป็นไอคอนเล็กแยกคอลัมน์ "ระบบบัญชี" (ซิงก์แล้ว / รอส่ง / ไม่ตรง / ล้มเหลว) แสดงเฉพาะเมื่อมี connector
2. **โหมดเริ่มต้น "ไม่ได้เชื่อม ERP"**: ซ่อนเมนู "ไม่ตรงกับ ERP", KPI ERP บนภาพรวม, timeline การซิงก์ใน side panel, คอลัมน์/tab "ยังไม่ map ERP" ในหน้าลูกค้า; ท้าย sidebar แสดง "ไม่ได้เชื่อมระบบบัญชี · ตั้งค่า" แทน — ใส่ toggle ดูตัวอย่างทั้ง 2 โหมด (ไม่เชื่อม / เชื่อม 1 ตัว)
3. **เมื่อเชื่อม ERP**: เปลี่ยนชื่อเมนูเป็น "คิวเชื่อมระบบบัญชี" (ไม่ตรง · รอส่งซ้ำ · ถูกปฏิเสธ · รออนุมัติ) ตัวนับ sidebar = รายการที่ต้องทำเท่านั้น; ข้อความใช้ชื่อ connector จริง เช่น "ส่งเข้า Express" / "ส่งเข้า KRS"
4. **วางบิลจบในตัวเอง**: stepper = เลือกลูกค้า+งวด → ติ๊ก DO → ตรวจ → **ออกเอกสาร** (ใบวางบิล / ใบแจ้งหนี้-ใบกำกับภาษี / ใบเสร็จ ตามเงื่อนไขลูกค้า) — "ส่งเข้าระบบบัญชี" เป็นปุ่มเสริมหลังออกเอกสารเมื่อมี connector; ย้าย "ดูตัวอย่าง payload" ไปไว้ใน log ที่ ตั้งค่า > การเชื่อมต่อ; แยก VAT: ค่าขนส่งยกเว้น / บริการประกอบ 7% ตามเงื่อนไขลูกค้า
5. **เพิ่มหน้า "รับชำระ"** (กลุ่มบัญชี): บันทึกรับเงินต่อใบแจ้งหนี้ (เต็ม/บางส่วน, วิธีรับ, เลขอ้างอิง, หัก ณ ที่จ่ายที่ลูกค้าหัก) + aging ลูกหนี้; หน้า Settlement เพิ่มบันทึกจ่าย + ออกหนังสือรับรอง 50 ทวิ
6. **ใบลดหนี้/เพิ่มหนี้**: เอกสารที่ "ออกแล้ว" แก้ไม่ได้ ต้องออกใบลดหนี้/เพิ่มหนี้อ้างใบเดิม
7. **Export สำหรับคนไม่มี ERP**: ปุ่ม "ส่งออกให้นักบัญชี" (Excel/CSV รายการขาย, รับชำระ, จ่ายรถร่วม, หัก ณ ที่จ่าย) เลือกรูปแบบไฟล์ได้ (ทั่วไป / Express / PEAK / FlowAccount)
8. **หน้าลูกค้า**: สถานะลูกค้ามีแค่ ใช้งาน / ปิดใช้; การ map รหัสต่อ connector อยู่ใน tab "รหัสระบบบัญชี" แสดงเฉพาะเมื่อมี connector
9. **ตั้งค่า > การเชื่อมต่อ**: การ์ด connector ทุกตัวเท่ากัน (KRS, Express, PEAK, FlowAccount, SAP B1, API ทั่วไป) แต่ละการ์ดมี เชื่อมต่อ/ทดสอบ/ดู log, ตาราง mapping ประเภทค่าใช้จ่าย ↔ รหัสสินค้าในระบบบัญชี, วันที่เริ่มซิงก์, และ "ใครออกเลขเอกสาร" (TMS / ระบบบัญชี)
10. แก้ตัวนับ sidebar ให้ตรงกับ KPI ของหน้า (ไม่ตรงกับ ERP 11 vs 4, Rate card 3 vs 2)

คงสี ฟอนต์ badge ภาษาไทย และข้อห้ามเดิมทั้งหมด (หน้าตาจะปรับในรอบถัดไป)

## รอบ 2 — หน้าตาแนว Shipsy (ใกล้เคียง ไม่ต้องเหมือนเป๊ะ)

ปรับ visual ของ TMS v2 ให้ดูเป็นผลิตภัณฑ์จริง อ้างอิงแนวทาง Shipsy แบบใกล้เคียง (ห้ามใช้โลโก้/ข้อความ/ภาพของเขา) — คงโครงหน้า ภาษาไทย และ flow จากรอบ 1 ทั้งหมด

**Token**
- (ชุดสีของเราเอง ปรับ 4 พ.ย. 2569 — ไม่ซ้ำค่าใดในเว็บ Shipsy) พื้นหน้า `#F4F5F2` (เทาหิน ไม่ใช่ครีม), พื้นรอง/sidebar `#EBEDE8`, การ์ด `#FFFFFF`, ขอบ `#D9DCD4`, เส้นในตาราง `#E4E6E0`
- ข้อความสีทึบ ไม่ใช้ rgba โปร่งใส: หลัก `#101418`; รอง `#3B424C` (≥8.6:1); จาง `#59606B` (≥5.4:1, ใช้แค่ placeholder/หมายเหตุ) — ห้ามอ่อนกว่า `#59606B` ยกเว้น disabled
- Accent เดียว `#2257C4` (hover `#1B479F`, พื้นอ่อน `#E9F0FA`, ขอบ/focus `#9DB6E3`) สำหรับปุ่มหลัก ลิงก์ เลขเอกสาร focus; navy `#13213F` เฉพาะหัวข้อ/โลโก้ — เลิกใช้ amber เป็นปุ่มหลัก amber เหลือแค่สถานะ "รอคน"
- สถานะ (ตัวอักษร/จุด บนพื้นอ่อน): สำเร็จ `#17733F` / `#E6F4EC`, รอ `#8F5500` / `#FCF0DC`, ผิดพลาด `#B3322A` / `#FBE9E7`, กำลังทำ `#2257C4` / `#E9F0FA`, ร่าง/ปิด `#3B424C` / `#ECEDEA` — ทุกคู่ ≥5:1
- เงา `0 6px 20px rgba(10,23,52,.07)` (การ์ด), `0 18px 44px rgba(10,23,52,.10)` (panel/dialog); มุม input 8px, การ์ด 14px, panel/dialog 20px, ปุ่ม/chip pill
- IBM Plex Sans Thai คงเดิม; หัวหน้า 24/600, หัวการ์ด 16/600, ตาราง 14/400, label 12.5/500 สีรอง; eyebrow เหนือหัวหน้า 12/600 สี accent; ตัวเลข tabular-nums

**Badge**: ในตารางใช้จุด 6px + ข้อความสีเดียวกับจุด ไม่มีพื้น; ป้ายพื้นจาง (สีสถานะ 12%) ใช้เฉพาะหัว side panel, KPI และรายการตรวจ — ห้าม badge พื้นทึบตัวขาว

**ลำดับความสำคัญ**: ไม่ต้องมี KPI 4 ใบทุกหน้า — หน้า list (ลูกค้า, รถ, rate card) ใช้แถบสรุปบรรทัดเดียว; KPI card ใช้เฉพาะ ภาพรวม, วางบิล, Settlement; หนึ่งการ์ดมีตัวเลขเด่นได้ 1 ตัว

**Pattern การ์ด**
1. Settlement side panel = "การ์ดตรวจบิล": ยอดที่รถร่วมเรียก (ขีดฆ่าถ้าต่าง) → ยอดอนุมัติตัวใหญ่สี accent; รายการตรวจทีละข้อ (POD ครบ · ราคาตรง rate card · ค่าใช้จ่ายหน้างานมีหลักฐาน · หักเงินเบิก/หัก ณ ที่จ่าย · เทียบ SO·DO·เที่ยว·ใบแจ้งหนี้รถร่วม) แต่ละข้อ: ไอคอนในกรอบ 28px มุม 8px + ชื่อ + คำอธิบาย + ป้ายพื้นจางขวา; ท้ายการ์ด progress "ตรวจแล้ว 4/5" + ปุ่ม pill "อนุมัติ"
2. จ่ายงานรถร่วม / "เสนอรถ" = การ์ดเปรียบเทียบ: ซ้ายเงื่อนไขงาน (น้ำหนัก, ประเภทรถ, กำหนดส่ง, เส้นทาง); ขวา 3 ตัวเลือก (รถบริษัท / รถร่วมประจำ / รถร่วมอื่น) แต่ละใบมีคะแนนตัวใหญ่ + แถบ ต้นทุน · ตรงเวลา · ความจุ; ใบแนะนำขอบ accent + ป้าย "แนะนำ"
3. Side panel ทุกหน้า: timeline ขั้นตอนเป็นแถวการ์ดพื้นจาง ไอคอนในกรอบซ้าย, ชื่อขั้น + เวลา, ✓ สี accent เมื่อเสร็จ

## รอบ 3 — ส่วนที่ยังขาด (เพิ่มหน้าใหม่)

ใช้ design system จากรอบ 2

1. **เที่ยวรถ / ใบคุมรถ**: เที่ยวหนึ่งรวมหลาย DO หลายจุดส่ง (จุดรับ/ส่งเรียงลำดับ, รถ + คนขับ + หาง เป็นค่าของเที่ยวนั้น); กระดานวางแผนลาก DO เข้าเที่ยว; หน้าติดตามรถและค่าเที่ยวรถร่วมอิงเที่ยว
2. **Driver app (มือถือ 390px ไฟล์แยก)**: รายการงานวันนี้ → รับงาน → ถึงจุด/ออกจากจุด (กดได้เมื่ออยู่ในระยะ หรือกรอกเหตุผล) → POD (รูป/ลายเซ็น/จำนวนที่ส่งจริง ตั้งได้ว่าบังคับ) → แจ้งปัญหาพร้อมรูป + reason; แถบสถานะ offline "รอส่ง 3 รายการ"
3. **หน้ารถร่วมจากลิงก์ LINE (มือถือ ไม่ต้อง login)**: ดูใบสั่งงาน → รับ (กรอกทะเบียน+คนขับ) / ปฏิเสธ; อัปโหลด POD ด้วยเลข DO; ดูใบจ่ายเงินและ 50 ทวิ ของตัวเอง
4. **รายงาน**: กำไรต่อเที่ยว/ลูกค้า/รถ, ลูกหนี้คงค้าง, ต้นทุนรถร่วม, ตั้งเวลาส่งรายงานทางอีเมล/LINE
5. **เงินเบิกล่วงหน้าคนขับ** + เคลียร์ค่าใช้จ่าย
6. **Template พิมพ์ A4**: ใบส่งของ, ใบวางบิล, ใบกำกับภาษี/ใบเสร็จ, ใบสำคัญจ่ายรถร่วม, 50 ทวิ
7. **Empty state** ของทุกหน้า

## รอบ 4 — One Platform: สมัครเอง, แพ็กเกจ, Platform Console

ใช้ design system จากรอบ 2 รายละเอียดเหตุผลอยู่ใน research/one-platform.md

1. **หน้าราคา + สมัคร (สาธารณะ, ไม่มี sidebar)**: การ์ดแพ็กเกจ 3 ใบ (เริ่มต้น · มาตรฐาน · องค์กร) คิดต่อรถ active/เดือน, toggle รายเดือน/รายปี, ป้าย "ทดลอง 30 วัน ไม่ต้องใช้บัตร"; ตารางเปรียบเทียบแบ่งหมวด เซลล์เป็น ✓ / "ซื้อเพิ่ม" / ตัวเลขโควตา; สมัคร 3 ขั้น (บัญชี + OTP มือถือ → ข้อมูลบริษัท: เลขผู้เสียภาษี 13 หลักแล้วเติมชื่อ/ที่อยู่ให้, สาขา, จำนวนรถ, โปรแกรมบัญชีที่ใช้ → เลือกแพ็กเกจ) ฝั่งขวาแสดงขั้นตอนเริ่มใช้งาน 3 ขั้น
2. **ในแอปลูกค้า — setup checklist** บนภาพรวมจนกว่าจะครบ (ตั้งค่าบริษัท → เพิ่มรถ → เพิ่มคนขับ → เชิญทีม → สร้าง SO แรก → เชื่อมระบบบัญชี) + banner สถานะ (ทดลองเหลือ X วัน / ค้างชำระ / อ่านอย่างเดียว)
3. **ตั้งค่า > แพ็กเกจและการเรียกเก็บเงิน (ลูกค้า)**: การ์ดแพ็กเกจปัจจุบัน (ชื่อ ราคา รอบบิล วันต่ออายุ), แถบโควตา (รถ active 12/20, ผู้ใช้, พื้นที่ POD, connector), ตารางโมดูล ✓ / 🔒 ในแพ็กเกจสูงกว่า / add-on ที่ซื้อแล้ว, ปุ่มเปลี่ยนแพ็กเกจ (dialog เทียบราคาแบบคิดตามสัดส่วน), ซื้อ add-on, ยกเลิกเมื่อครบรอบ, ประวัติใบกำกับภาษี/ใบเสร็จ, วิธีชำระ (บัตร / PromptPay QR / โอน + แนบสลิป)
4. **Platform Console (แอปแยกของทีมเรา, sidebar ของตัวเอง, แถบบนสีต่างจากแอปลูกค้าให้รู้ว่าเป็นโหมดผู้ดูแล)**:
   - ภาพรวม: ลูกค้าตามสถานะ, MRR, ทดลองใกล้หมด 7 วัน, อัตราเปลี่ยนเป็นจ่ายจริง, รถ active รวม
   - ลูกค้า: ตาราง (บริษัท, เลขผู้เสียภาษี, แพ็กเกจ, สถานะ, รถ active/โควตา, ต่ออายุ, ยอดค้าง, sales) → side panel/หน้ารายละเอียด tab ภาพรวม · Subscription · การใช้งาน · ผู้ใช้ · สิทธิ์พิเศษ · ใบแจ้งหนี้ · log; การกระทำ: เปลี่ยนแพ็กเกจ, ขยายทดลอง, ส่วนลด, ระงับ/ปลด, "เข้าใช้งานแทน" (dialog บังคับเหตุผล + แถบเตือนตลอดเวลาที่ impersonate)
   - คิวอนุมัติการสมัคร: เทียบข้อมูลที่กรอกกับข้อมูลนิติบุคคล, เตือนเลขซ้ำ, อนุมัติ/ปฏิเสธพร้อมเหตุผล
   - แพ็กเกจ: รายการ + เวอร์ชัน, ตัวแก้ feature matrix (แถว feature แบ่งหมวด × คอลัมน์แพ็กเกจ, เซลล์ toggle ✓ / ซื้อเพิ่ม / ช่องตัวเลข limit), ราคา, แสดงบนเว็บไหม, preview หน้าราคา; บันทึกราคาใหม่ = เวอร์ชันใหม่ ลูกค้าเดิมคงราคาเดิม
   - Add-on และคูปอง, การเงินแพลตฟอร์ม (ใบกำกับที่ออกให้ลูกค้า, ตรวจสลิป, ค้างชำระ), ทีมงานและสิทธิ์ (owner / sales / support / finance), audit log
5. สถานะลูกค้า (badge ไทย): รอยืนยัน · ทดลองใช้ · ใช้งาน · ค้างชำระ · อ่านอย่างเดียว · ระงับ · ยกเลิก

## รอบ 5: Driver App — มาตรฐานแอปมือถือ + function ที่ขาด (ส่งแล้ว 4 พ.ย. 2569)

**ลดความเป็น AI:** เลิก monospace กับตัวเลข (ใช้ Plex Sans Thai + tabular-nums, เงินมี ฿); เอาป้าย "รอส่ง 3" ออกจาก header ทุกจอ เหลือไอคอน sync ตอนมีคิวค้าง; ใช้ list row แทนการ์ดซ้อนการ์ด และให้มี callout สีไม่เกิน 1 อันต่อจอ; จอสำเร็จเลิกใช้แผ่นเขียวเต็มจอ; แจ้งปัญหาเปลี่ยน grid ไอคอนเป็น radio list; ตรวจรถใช้ segmented control + ปุ่ม "ปกติทั้งหมด" (ข้อวิกฤตผิดปกติแล้วห้ามออกรถ); POD ใช้ step/checkbox + thumbnail; จอ tab หลักไม่มีปุ่ม back; ปุ่ม disabled เป็นสีเทา; input สูง 52px และเบอร์โทรมี +66

**จอที่เพิ่ม:** M10 ขอสิทธิ์ + PDPA · M11 รับ/ปฏิเสธงาน · M12 ขึ้นของต้นทาง (สแกน, รูป, เลขซีล) · M13 ส่งไม่สำเร็จ/ส่งบางส่วน · M14 เวลารอลงของ · M15 ฟอร์มค่าใช้จ่าย · M16 จบเที่ยว/คืนเงินทอน · M17 คิวส่งข้อมูล offline · M18 แจ้งเตือนจากฝ่ายจัดรถ

## รอบ 6: Driver App (ทำต่อ) + เติม fleet + ฟอนต์ทั้งระบบ (ส่งแล้ว 4 พ.ย. 2569)

รอบนี้มี 3 ส่วน ทำตามลำดับ

== ส่วน 1: ทำงาน Driver App ข้อความก่อนหน้าต่อให้จบ ==
รอบที่แล้วหยุดไปหลัง "Searching ×2, Reading" และยังไม่ได้แก้ไฟล์ ให้ทำตามข้อความล่าสุดก่อนหน้านี้ทั้งหมด: ส่วน A ข้อ 1–10 และส่วน B จอ M10–M18 ในไฟล์ TMS Driver App

== ส่วน 2: เติมหมวด "รถ" (fleet) ใน TMS v4 ==
ของเดิมที่มีอยู่ให้คงไว้ทั้งหมด ได้แก่ ทะเบียนรถ, โปรไฟล์รถ, ใบสั่งซ่อม, ปฏิทินซ่อมบำรุง, น้ำมันและค่าใช้จ่าย, เอกสารรถ, คนขับและผู้รับเหมา
เพิ่มเมนูและหน้าต่อไปนี้ในกลุ่ม "รถ":

1. ยาง: ทะเบียนยางรายเส้น (เลขยาง ยี่ห้อ ขนาด ราคา วันติดตั้ง) และผังตำแหน่งยางตามประเภทรถ (6 ล้อ / 10 ล้อ / หัวลาก+หาง) แบบคลิกเลือกตำแหน่งได้
   - บันทึกความลึกดอกยาง (มม.) และประวัติการสลับ ถอด หล่อดอก
   - แจ้งเตือนเมื่อดอกต่ำกว่าเกณฑ์
   - ต้นทุนต่อ กม. รายเส้น
   - เพิ่มแท็บ "ยาง" ในโปรไฟล์รถ
2. อุบัติเหตุและเคลม
   - ข้อมูลเคส: วันเวลา สถานที่ รถ คนขับ คู่กรณี เลขแจ้งความ รูป
   - การเคลม: บริษัทประกัน เลขเคลม ค่าเสียหายส่วนแรก (deductible) ยอดเคลม ยอดได้รับ
   - ผล: ฝ่ายผิด และการหักเงินคนขับ (ส่งไปเงินเดือน/Settlement)
   - ผูกกับใบสั่งซ่อม
   - สถานะ: แจ้งเหตุ → ยื่นเคลม → ประกันอนุมัติ → ซ่อม → ปิด
3. ใบสั่งและค่าปรับจราจร
   - บันทึกหรือนำเข้า: ทะเบียน วันเวลา ประเภท (ขับเร็ว จอดห้าม น้ำหนักเกิน) จำนวนเงิน กำหนดชำระ
   - จับคู่คนขับอัตโนมัติจากเที่ยวรถในช่วงเวลานั้น
   - เลือก "หักคนขับ / บริษัทจ่าย"
   - สถานะ: รอชำระ / ชำระแล้ว / หักแล้ว
4. กฎห้ามจ่ายงานในกระดานวางแผนและหน้าจ่ายงานรถร่วม
   - เงื่อนไขที่จ่ายงานไม่ได้:
     - รถที่สถานะซ่อม/จอด
     - ประกัน พ.ร.บ. ภาษี หรือ ตรอ. หมดอายุ
     - ตรวจรถก่อนออกไม่ผ่านข้อวิกฤต
     - คนขับใบขับขี่หมด หรือประเภทใบขับขี่ไม่ตรงประเภทรถ
   - รถในกระดานแสดงเป็นสีเทา มีป้ายเหตุผล และปุ่ม "ดูสาเหตุ"
   - ใช้กับรถร่วมด้วย
   - ผู้จัดการ override ได้ แต่ต้องใส่เหตุผลและบันทึกลง log
5. ผลตรวจรถก่อนออก
   - รายการผลตรวจจากแอปคนขับ (M7) ต่อวัน: รถ คนขับ เวลา ผ่าน/ไม่ผ่าน จำนวนข้อบกพร่อง รูป
   - รายการข้อบกพร่องที่ยังไม่แก้ พร้อมปุ่ม "เปิดใบสั่งซ่อม" ที่ดึงข้อมูลและรูปเข้า WO ให้อัตโนมัติ
   - รถที่ยังไม่ตรวจวันนี้
6. ผู้ขาย/อู่ซ่อม (อยู่ในข้อมูลหลัก)
   - ข้อมูล: ชื่อ เลขผู้เสียภาษี ประเภท (อู่ ร้านยาง ร้านอะไหล่ ปั๊ม ประกัน) เครดิตเทอม ราคาประจำ
   - คะแนนและสถิติ: ระยะเวลาซ่อมเฉลี่ย ยอดซื้อรวม
   - ในใบสั่งซ่อม ให้เลือกอู่จากรายการนี้แทนการพิมพ์ชื่อเอง
7. คะแนนพฤติกรรมคนขับ (จาก GPS)
   - ข้อมูลที่ใช้: ขับเร็วเกินกำหนด เบรกแรง จอดติดเครื่อง ขับต่อเนื่องเกิน 4 ชม. (กฎกรมการขนส่งทางบก) ชั่วโมงขับต่อวัน
   - หน้าแสดงคะแนนรายคนต่อเดือน และ ranking
   - แท็บในโปรไฟล์คนขับ
8. อะไหล่และสต็อก (สำหรับอู่ของบริษัท)
   - รายการอะไหล่: รหัส ชื่อ จำนวนคงเหลือ จุดสั่งซื้อ ต้นทุนเฉลี่ย
   - รับเข้า / เบิกเข้าใบสั่งซ่อม
   - แจ้งเตือนของใกล้หมด
9. ถังน้ำมันบริษัท
   - รับน้ำมันเข้าถัง (ลิตร ราคา ผู้ขาย) และจ่ายออกให้รถรายคัน
   - วัดยอดคงเหลือ และกระทบยอดส่วนต่าง
   - แจ้งเตือนส่วนต่างผิดปกติ
10. ลีสซิ่ง/เช่าซื้อ
    - ในโปรไฟล์รถ: ผู้ให้เช่าซื้อ ค่างวด วันครบกำหนด จำนวนงวดคงเหลือ ยอดคงเหลือ
    - ค่างวดนับรวมในต้นทุน/กม.
    - แจ้งเตือนงวดใกล้ครบ
11. ประวัติเลขไมล์
    - ดึงจาก GPS อัตโนมัติ แก้มือได้แต่ต้องใส่เหตุผล
    - ตรวจจับเลขไมล์ถอยหลังหรือกระโดดผิดปกติ
    - แสดงในโปรไฟล์รถ
12. หางพ่วง/หางลาก เป็นทรัพย์สินแยก
    - มีทะเบียน เอกสาร และ PM ของตัวเอง
    - ประวัติการพ่วงกับหัวลาก (วันพ่วง วันปลด)
13. แจ้งเตือนเอกสารใกล้หมด
    - ตั้งค่าล่วงหน้า 60 / 30 / 7 วัน
    - ช่องทาง LINE / อีเมล / ในระบบ
    - กำหนดผู้รับผิดชอบรายประเภทเอกสาร
14. วงเงินอนุมัติใบสั่งซ่อมตามตำแหน่ง (อยู่ในตั้งค่า)
    - เช่น หัวหน้าช่างอนุมัติได้ไม่เกิน ฿5,000.00 และผู้จัดการไม่เกิน ฿50,000.00
    - เกินวงเงินต้องส่งขึ้นไปอนุมัติลำดับถัดไป
15. รายงาน fleet (อยู่ในเมนูรายงาน)
    - ต้นทุนต่อ กม. แยกรายคันและประเภทรถ
    - อัตรากินน้ำมัน ranking
    - % เวลาที่รถหยุดซ่อม (downtime)
    - % PM ตรงเวลา
    - ต้นทุนตลอดอายุรถ (TCO)
    - ต้นทุนยาง
    - ค่าปรับต่อคนขับ

ทุกหน้าใหม่ต้องใช้ pattern เดิม: KPI ด้านบน, แท็บสถานะ, ตาราง filter, drawer รายละเอียด, empty state
ใช้ข้อมูลตัวอย่างไทยที่สมจริงและสอดคล้องกับทะเบียนรถที่มีอยู่

== ส่วน 3: ปรับฟอนต์ทั้งระบบให้เป็นมืออาชีพ ไม่ดูเป็น AI ==

  - ละติน: IBM Plex Sans
  - จีน: Noto Sans SC
- ฟอนต์เอกสารพิมพ์ A4 (ใบกำกับภาษี ใบวางบิล ใบเสร็จ 50 ทวิ ใบคุมรถ ใบสั่งซ่อม): Sarabun
- scale และน้ำหนัก:
  - หัวหน้า 22/600
  - หัวการ์ด/section 15/600
  - เนื้อหา/ตาราง 14/400
  - label 12.5/500
  - ตัวเลข KPI 28/600 (ไม่ใช่ 700)
  - ห้ามใช้ตัวหนาเกิน 600
  - line-height ภาษาไทย 1.6 และหัวข้อ 1.35
  - letter-spacing 0
  - ห้ามตัวอักษรเล็กกว่า 12px
- ทะเบียนรถเขียนแบบ "71-0457 กทม." น้ำหนัก 500 สีข้อความหลัก

## รอบ 9: drawer ทุกตัว + กระดานวางแผน (ส่งแล้ว 4 พ.ย. 2569)

== ส่วน A: Drawer รายละเอียด (เริ่มที่ drawer ใบสั่งขนส่ง SO แล้วใช้ pattern เดียวกันกับ DO, เที่ยวรถ, ใบสั่งซ่อม, อุบัติเหตุ, เอกสาร ฯลฯ) ==

ปัญหาปัจจุบัน:
- ส่วน "เส้นทางจาก rate card" ให้เลือก radio จากทุกเส้นทาง ทั้งที่ SO มีเส้นทางแล้ว
- ชื่อเส้นทางเป็นชิปเทาทุกแถว และการ์ดที่เลือกเป็นพื้นฟ้า
- drawer แคบ ข้อมูลเป็นแถวยาวไม่มีกลุ่ม
- "ที่มา: มือ" อ่านไม่รู้เรื่อง
- "เกินกำหนด" ไม่มีสี

แก้เป็น:
1. ความกว้าง 600px (จอแคบ 100%)
2. หัว drawer:
   - บรรทัด 1: ประเภทเอกสาร (12.5/500 สีรอง)
   - บรรทัด 2: เลขเอกสาร (18/600 สี accent) + ป้ายสถานะ
   - บรรทัด 3: ชื่อลูกค้า + เลข PO ลูกค้า (สีรอง)
   - ขวาบน: เมนู ⋯ (แก้ไข / คัดลอกเป็นใบใหม่ / พิมพ์ / ยกเลิกเอกสาร) + ปุ่มปิด
3. แท็บ: สรุป / สินค้า / เอกสารแนบ / กิจกรรม (timeline สถานะ ใครทำ เมื่อไหร่ รวม log ระบบ)
4. แท็บสรุป แบ่งเป็น section มีหัวข้อเล็ก 12.5/600 สีรอง และเส้นคั่น section:
   - ข้อมูลงาน: grid 2 คอลัมน์ label/ค่า
     - ช่องข้อมูล: ลูกค้า, รหัสลูกค้า, ประเภทรถที่ต้องการ, น้ำหนัก/ปริมาตร, กำหนดส่ง, ที่มา
     - กำหนดส่งที่เกินกำหนดเป็นสีแดง #B3322A พร้อมข้อความ "เกิน 1 วัน"
     - ที่มาใช้คำ: สร้างเอง / นำเข้า CSV / API / ERP
   - จุดรับ–ส่ง: ลำดับแนวตั้งมีเส้นเชื่อม (จุด 1 รับ, จุด 2 ส่ง …) แต่ละจุดแสดง:
     - ชื่อสถานที่ ที่อยู่ย่อ ช่วงเวลา ผู้ติดต่อ + เบอร์
   - รถ/คนขับ:
     - ถ้ายังไม่จัด: ข้อความ "ยังไม่จัดรถ" + ปุ่ม text "จัดรถ"
     - ถ้าจัดแล้ว: ทะเบียน คนขับ เที่ยวรถ (ลิงก์)
   - ราคา: ตารางแจกแจงชิดขวา (ไม่ใช่ radio list)
     - ค่าขนส่งตาม rate card (เส้นทาง อยุธยา → สระบุรี · พ่วง · 65 กม.)

== Open API (เมนูใหม่: ตั้งค่า → นักพัฒนา / Open API) ==
เป้าหมาย: ลูกค้า (บริษัทขนส่ง) และคู่ค้าของเขา (ผู้ส่งสินค้า, ERP, WMS, e-commerce) เชื่อมกับ TMS เองได้ โดยไม่ต้องให้ทีมเราทำ integration ให้ทีละราย — แยกจาก "connector ERP" ที่มีอยู่ (connector = เราเขียนให้, Open API = ลูกค้าต่อเอง)

1. ภาพรวม API (หน้าแรก)
- สถานะ: API เปิด/ปิด ตามแพ็กเกจ, โควตาเดือนนี้ (เรียกไปแล้ว / ลิมิต), error rate 24 ชม., latency p95
- ลิงก์: เอกสาร API, OpenAPI spec (ดาวน์โหลด openapi.yaml), Postman collection, สถานะระบบ (status page)
- สลับโหมด Sandbox / Production (ป้ายสีส้ม "SANDBOX" ชัดเจนเมื่ออยู่ในโหมดทดสอบ — ข้อมูลแยกกัน)

2. API keys
- ตาราง: ชื่อ key, prefix (เช่น tms_live_8f3a…), โหมด (live/test), scope, IP ที่อนุญาต, สร้างโดย, สร้างเมื่อ, ใช้ล่าสุด, หมดอายุ, สถานะ
- "+ สร้าง API key": ชื่อ, โหมด, scope แบบ checkbox (อ่าน/เขียน แยกตาม resource), IP allowlist (ไม่บังคับ), วันหมดอายุ (30/90/365 วัน/ไม่หมด)
- หลังสร้าง แสดง secret เต็ม "ครั้งเดียว" + ปุ่มคัดลอก + คำเตือน (monospace เฉพาะช่องนี้)
- การกระทำ: หมุนเวียน key (rotate, key เก่าใช้ได้อีก 24 ชม.), เพิกถอน (ยืนยัน + เหตุผล), แก้ scope
- Scope ตัวอย่าง: orders:read, orders:write, shipments:read, tracking:read, pod:read, invoices:read, master:read, master:write, vehicles:read, webhooks:manage

3. Webhooks
- ตาราง endpoint: URL, event ที่สมัคร, สถานะ (ใช้งาน/ปิด/ล้มเหลวต่อเนื่อง), อัตราสำเร็จ 7 วัน, ส่งล่าสุด
- "+ เพิ่ม endpoint": URL (https เท่านั้น), เลือก event, signing secret (แสดงครั้งเดียว), header เพิ่มเติม
- Event ตัวอย่าง: order.created, order.updated, order.cancelled, shipment.assigned, shipment.picked_up, shipment.arrived, shipment.delivered, shipment.failed, pod.uploaded, trip.started, trip.completed, invoice.issued, invoice.paid, vehicle.document_expiring
- รายละเอียด endpoint: ประวัติการส่ง (event, เวลา, HTTP status, เวลาตอบ, จำนวนครั้งที่ลองใหม่), ดู payload/response, ปุ่ม "ส่งซ้ำ", ปุ่ม "ส่ง event ทดสอบ"
- นโยบาย retry: ลองใหม่แบบ exponential backoff 8 ครั้งใน 24 ชม.; ล้มเหลวต่อเนื่องเกินเกณฑ์ → ปิดอัตโนมัติ + แจ้งอีเมลผู้ดูแล
- แสดงวิธีตรวจลายเซ็น (HMAC-SHA256 ใน header X-TMS-Signature + timestamp กัน replay)

4. Log การเรียก API
- ตาราง: เวลา, method, path, HTTP status, เวลาตอบ (ms), API key, IP, request id
- filter: ช่วงเวลา, status (2xx/4xx/5xx), key, path
- drawer: request/response (ซ่อนข้อมูลอ่อนไหว), request id สำหรับแจ้ง support
- เก็บย้อนหลัง 30 วัน (ตามแพ็กเกจ)

5. เอกสาร API (หน้าในระบบหรือแท็บ "เอกสาร")
- โครง: เริ่มต้นใช้งาน (auth ด้วย Bearer token, base URL live/sandbox), แนวทาง (pagination แบบ cursor, idempotency-key สำหรับ POST, rate limit + header X-RateLimit-*, รูปแบบ error มาตรฐาน {code, message, details, request_id}, เวลาเป็น ISO 8601 + Asia/Bangkok, เงินเป็น string ทศนิยม 2 ตำแหน่ง, versioning /v1)
- Resource หลัก: Orders (SO), Shipments (DO), Trips, Tracking (ตำแหน่งล่าสุด + ETA), POD (รูป ลายเซ็น ชื่อผู้รับ), Customers, Locations/Addresses, Vehicles, Drivers, Rate quote (ขอราคาจาก rate card), Invoices, Payments, Documents (PDF)
- แต่ละ endpoint: คำอธิบาย, พารามิเตอร์, ตัวอย่าง request/response, scope ที่ต้องใช้, ปุ่ม "ลองเรียก" ใน sandbox
- ตัวอย่างโค้ด: cURL, JavaScript, Python, PHP (แท็บสลับภาษา) — แสดงเป็น code block monospace
- Changelog API

6. ขีดจำกัดและแพ็กเกจ
- rate limit ต่อ key (เช่น 60 req/นาที เริ่มต้น, 300 มาตรฐาน, 1,000 องค์กร) และโควตารายเดือน
- Open API เปิดได้ในแพ็กเกจมาตรฐานขึ้นไป; webhook จำนวน endpoint ตามแพ็กเกจ
- เชื่อมกับหน้า "แพ็กเกจและการเรียกเก็บเงิน" (แสดงการใช้ API เป็น usage)

7. ความปลอดภัยและสิทธิ์
- เฉพาะ role ผู้ดูแลระบบ/นักพัฒนา เข้าเมนูนี้ได้
- ทุกการสร้าง/หมุน/เพิกถอน key และแก้ webhook บันทึกลง audit log
- แจ้งเตือนเมื่อ key ใกล้หมดอายุ / ถูกใช้จาก IP ใหม่ / error พุ่ง

8. Platform Console (ฝั่งเรา)
- ดูการใช้ API ของทุก tenant, ปิด API ของ tenant ที่ละเมิด, ปรับ rate limit รายลูกค้า

9. ฝั่งคู่ค้าของลูกค้า (ทางเลือก)
- ผู้ส่งสินค้า (shipper) ของลูกค้าขอ key แบบจำกัดเฉพาะงานของตัวเอง (scope: orders:write + tracking:read ของลูกค้ารายนั้น) — สร้างจากหน้าลูกค้าใน ข้อมูลหลัก → ลูกค้า → แท็บ "การเชื่อมต่อ API"

== ช่องว่างอื่นที่ตรวจเจอ ==
A. ตั้งค่า → การเชื่อมต่อ: ตอนนี้การ์ด KRS อยู่ตัวแรกและถูกเลือกค้างเป็นค่าเริ่มต้น ("ตั้งค่า KRS") — ต้องเป็นกลาง: เรียง "ไม่เชื่อม (ใช้ TMS ออกเอกสารเอง)" เป็นค่าเริ่มต้นตัวแรก ตามด้วย connector เรียงตามตัวอักษร ไม่มีตัวไหนถูกเลือกจนกว่าจะกด "เชื่อมต่อ"; การ์ด "API ทั่วไป" ให้ลิงก์ไปหน้า Open API
B. ข้อมูลหลัก เพิ่ม 4 หน้า:
  - สถานที่/จุดรับส่ง (address book): ชื่อ ที่อยู่ พิกัด (ปักหมุด) geofence รัศมี เวลาทำการ ผู้ติดต่อ ข้อจำกัด (รถเข้าได้สูงสุด) — SO เลือกจุดจากที่นี่
  - สินค้าและหน่วย: รหัส ชื่อ หน่วย (ถุง พาเลท ชิ้น ตัน) น้ำหนัก/ปริมาตรต่อหน่วย ประเภทพิเศษ (เปราะบาง อันตราย ควบคุมอุณหภูมิ)
  - ประเภทรถ: 4 ล้อ/6 ล้อ/10 ล้อ/พ่วง/เทรลเลอร์/ห้องเย็น น้ำหนักบรรทุก ปริมาตร ใบขับขี่ขั้นต่ำ — ใช้กับ rate card และกฎจ่ายงาน
  - ค่าบริการเสริม (accessorial): ค่ารอ (ต่อชม. หลังฟรี N ชม.) ค่าขึ้น/ลง ค่าค้างคืน ค่าจุดเพิ่ม fuel surcharge (% อิงราคาน้ำมัน) — แต่ละรายการตั้ง VAT ยกเว้น/7% และหัก ณ ที่จ่ายได้
C. ศูนย์แจ้งเตือน/ข้อยกเว้น (Exceptions) ใน ปฏิบัติการ: รวมทุกเหตุในที่เดียว — ล่าช้ากว่า ETA, ออกนอกเส้นทาง, จอดนาน, ส่งไม่สำเร็จ, POD ไม่ครบ, ตรวจรถไม่ผ่าน, เอกสารหมด, น้ำหนักเกิน — มีผู้รับผิดชอบ สถานะ (ใหม่/กำลังจัดการ/ปิด) และ SLA
D. รายงานเพิ่ม: OTIF / ส่งตรงเวลา % (รายลูกค้า รายเส้นทาง), POD ครบ %, อายุเจ้าหนี้รถร่วม (AP aging), สรุปภาษีหัก ณ ที่จ่าย/50 ทวิ รายเดือน
E. แจ้งลูกค้าปลายทางอัตโนมัติ: ตั้งค่า → การแจ้งเตือน เพิ่มแท็บ "แจ้งลูกค้า" — ส่ง SMS/LINE/อีเมล เมื่อ รถออก / ใกล้ถึง (ETA 30 นาที) / ส่งแล้ว (แนบลิงก์ติดตาม + POD) เลือกได้ต่อลูกค้า

จบแล้วเปิดดูหน้าจริง (Open API ภาพรวม, สร้าง API key, webhook, การเชื่อมต่อ, สถานที่) แล้วสรุปสิ่งที่ทำ/ยังไม่ได้ทำ

== 1. TMS Signup (สาธารณะ) ==
- หน้าราคา: header (โลโก้, เมนู ฟีเจอร์ / ราคา / ติดต่อ, ปุ่ม เข้าสู่ระบบ + "ทดลองใช้ฟรี"), toggle รายเดือน/รายปี (รายปีลด 2 เดือน), การ์ด 3 ใบ (มาตรฐานมีป้าย "นิยม"), ป้าย "ทดลอง 30 วัน ไม่ต้องใช้บัตร", ตารางเปรียบเทียบแบ่งหมวด (เซลล์ ✓ / "ซื้อเพิ่ม" / ตัวเลขโควตา), ตัวคำนวณราคา (ใส่จำนวนรถ → ราคาต่อเดือน), FAQ (คิดเงินยังไง นับรถร่วมไหม ยกเลิกได้ไหม ข้อมูลอยู่ที่ไหน ใช้กับโปรแกรมบัญชีไหนได้)
- สมัคร 3 ขั้น (stepper ด้านบน, ด้านขวาเป็นแผง "เริ่มใช้งานได้ใน 3 ขั้น"):
  ขั้น 1 บัญชี: ชื่อ-นามสกุล, อีเมลบริษัท, เบอร์มือถือ, รหัสผ่าน (หรือ "สมัครด้วย Google") → OTP 6 หลักทางมือถือ (นับถอยหลังขอใหม่ 60 วิ)
  ขั้น 2 บริษัท: เลขผู้เสียภาษี 13 หลัก → ปุ่ม "ค้นหา" เติมชื่อนิติบุคคล/ที่อยู่ให้อัตโนมัติ (แสดงแหล่ง "ข้อมูลจากกรมพัฒนาธุรกิจการค้า" + แก้ได้), สาขา (สำนักงานใหญ่/รหัสสาขา), จำนวนรถบริษัท / รถร่วมโดยประมาณ, โปรแกรมบัญชีที่ใช้ (ไม่มี / Express / FlowAccount / KRS / PEAK / SAP B1 / อื่นๆ), ยอมรับเงื่อนไขและนโยบายความเป็นส่วนตัว (PDPA)
  ขั้น 3 แพ็กเกจ: ค่าเริ่มต้น "ทดลองใช้มาตรฐาน 30 วัน" → ปุ่ม "เริ่มใช้งาน"
- state: เลขผู้เสียภาษีนี้มีในระบบแล้ว → "ส่งคำขอเข้าร่วมบริษัท" หรือ "ติดต่อเรา" (เข้าคิวอนุมัติ); ไม่พบเลขใน DBD → กรอกเองได้ + แจ้งว่าจะตรวจภายหลัง; OTP ผิด/หมดอายุ; รออนุมัติ (ถ้าตั้งนโยบายให้ทีมตรวจ) → หน้า "เราได้รับข้อมูลแล้ว จะแจ้งภายใน 1 วันทำการ"
- หน้าเข้าสู่ระบบ + ลืมรหัสผ่าน + เลือกบริษัท (กรณีผู้ใช้อยู่หลายบริษัท)

== 2. TMS v4 (แอปลูกค้า) ==
- Setup checklist บนหน้าภาพรวม (ซ่อนได้, หายเมื่อครบ): ตั้งค่าบริษัท → เพิ่มรถ (นำเข้า Excel) → เพิ่มคนขับ → เชิญทีม → สร้าง SO แรก → เชื่อมระบบบัญชี (ไม่บังคับ) — แถบ progress 3/6
- Banner สถานะบนสุดของทุกหน้า: ทดลองใช้เหลือ 12 วัน (ปุ่ม เลือกแพ็กเกจ) / ค้างชำระ เหลือ 5 วันก่อนเป็นอ่านอย่างเดียว (ปุ่ม ชำระเงิน) / อ่านอย่างเดียว (สร้างงานใหม่ไม่ได้ ดูและ export ได้) — ใช้ตัวสลับใน demo bar
- ตั้งค่า → แพ็กเกจและการเรียกเก็บเงิน:
  - การ์ดแพ็กเกจปัจจุบัน: ชื่อ ราคา รอบบิล วันต่ออายุ สถานะ
  - การใช้งานเดือนนี้: แถบโควตา รถ active 12/20 (รายการรถที่ถูกนับ คลิกดูได้), พื้นที่ POD, connector, API calls, ฟิลด์เพิ่มเติม, SMS/LINE
  - ตารางโมดูล: ✓ มี / 🔒 ในแพ็กเกจสูงกว่า (ปุ่ม ดูรายละเอียด) / add-on ที่ซื้อแล้ว
  - ปุ่ม เปลี่ยนแพ็กเกจ → dialog เทียบ 3 แพ็กเกจ + ยอดคิดตามสัดส่วนของรอบนี้; ซื้อ add-on; ยกเลิกเมื่อครบรอบ (บอกว่าข้อมูลเก็บไว้กี่วันและ export ได้)
  - วิธีชำระ: บัตร / PromptPay QR / โอน + แนบสลิป
  - ประวัติใบกำกับภาษี/ใบเสร็จที่เราออกให้ลูกค้า (ดาวน์โหลด PDF) — แยกชัดจากเอกสารที่ลูกค้าออกให้ลูกค้าของเขา
- ล็อกฟีเจอร์ตามแพ็กเกจ: เมนูของโมดูลที่ไม่มีในแพ็กเกจแสดงไอคอน 🔒 เปิดแล้วเป็นหน้าแนะนำโมดูล + ปุ่มอัปเกรด (ไม่ซ่อนเมนู); โควตาเต็มแสดงคำเตือนก่อนสร้างรายการใหม่ (เช่น รถ active ครบ 20 → add-on หรืออัปเกรด)
- ผู้ใช้หลายบริษัท: เมนูสลับบริษัทที่หัว sidebar (ตัวเลือกองค์กรเดิม) แสดงบริษัทที่เป็นสมาชิก

== 3. TMS Platform Console (ทีมเรา) ==
- แถบบนสีเข้ม navy #13213F + ป้าย "PLATFORM CONSOLE" ให้รู้ว่าเป็นโหมดผู้ดูแล; sidebar: ภาพรวม, ลูกค้า, คิวอนุมัติ, แพ็กเกจ, Add-on และคูปอง, การเงิน, การใช้งาน API, ทีมงาน, Audit log
- ภาพรวม: KPI ลูกค้าตามสถานะ, MRR, ทดลองใกล้หมด 7 วัน, อัตราเปลี่ยนเป็นจ่ายจริง, รถ active รวม, ค้างชำระรวม; กราฟ MRR 6 เดือน; รายการต้องจัดการวันนี้
- ลูกค้า: ตาราง (บริษัท, เลขผู้เสียภาษี, แพ็กเกจ, สถานะ, รถ active/โควตา, วันต่ออายุ, ยอดค้าง, sales ผู้ดูแล) → หน้า/drawer รายละเอียด แท็บ ภาพรวม · Subscription · การใช้งาน · ผู้ใช้ · สิทธิ์พิเศษ (override เปิด/ปิด/เพิ่ม limit + เหตุผล + ผู้อนุมัติ) · ใบแจ้งหนี้ · API · log
  การกระทำ: เปลี่ยนแพ็กเกจ, ขยายทดลองใช้, ให้ส่วนลด, ระงับ/ปลดระงับ, ปิด API, ปรับ rate limit, "เข้าใช้งานแทน" (dialog บังคับเหตุผล → เปิด TMS v4 พร้อมแถบเตือนสีส้มตลอดเวลา "กำลังใช้งานแทน บจก. … · ออก")
- คิวอนุมัติการสมัคร: เทียบข้อมูลที่กรอกกับข้อมูล DBD (ไฮไลต์ที่ต่างกัน), เตือนเลขผู้เสียภาษีซ้ำ, อนุมัติ/ปฏิเสธพร้อมเหตุผล; ตั้งนโยบาย "อนุมัติอัตโนมัติ / ต้องให้ทีมตรวจ"
- แพ็กเกจ: รายการ + เวอร์ชัน; ตัวแก้ feature matrix (แถว feature แบ่งหมวด × คอลัมน์แพ็กเกจ; เซลล์ toggle ✓ / ซื้อเพิ่ม / ช่องตัวเลข limit); ราคา; แสดงบนเว็บไหม; preview หน้าราคา; บันทึกราคาใหม่ = เวอร์ชันใหม่ ลูกค้าเดิมคงราคาเดิม (ปุ่ม "ย้ายลูกค้าเดิม" + กำหนดวันแจ้งล่วงหน้า)
- Add-on และคูปอง: รายการ ราคา เงื่อนไข จำนวนที่ใช้
- การเงิน: ใบกำกับภาษีที่ออกให้ลูกค้า (VAT 7% ค่าบริการซอฟต์แวร์), การชำระ, คิวตรวจสลิปโอน (รูปสลิป + ยอด + ยืนยัน/ปฏิเสธ), ค้างชำระ (aging), ส่งเตือน
- การใช้งาน API: ทุก tenant, ปิด API ของ tenant ที่ละเมิด, ปรับ rate limit
- ทีมงานและสิทธิ์: owner / sales / support / finance (support เข้าใช้งานแทนได้ แต่แก้แพ็กเกจไม่ได้; finance แก้การเงินได้)
- Audit log ทุกการกระทำของทีมเรา (ใคร ทำอะไร กับลูกค้ารายไหน เหตุผล เวลา)

หลักการออกแบบ: AI เสนอ คนยืนยันเสมอ — ทุกผลจาก AI แสดงเป็น "ร่าง" มีป้ายเล็ก "AI แนะนำ" (ไอคอน sparkle ขนาดเล็ก สีรอง ไม่ใช้ gradient/สีม่วง/เอฟเฟกต์เรืองแสง), แสดงความมั่นใจ (สูง/กลาง/ต่ำ) และแหล่งที่มา (ไฮไลต์ข้อความหรือกรอบบนรูปที่ AI อ่าน), ปุ่ม "ยอมรับ" / "แก้ไข" / "ปฏิเสธ" — ไม่มีอะไรบันทึกเองอัตโนมัติ

== 1. สร้าง SO จากข้อความ/ไฟล์ (Order intake) ==
- ปุ่มรองข้าง "+ สร้าง SO": "สร้างจากข้อความ/ไฟล์" (ในหน้า SO และทางลัดบนภาพรวม)
- dialog: วางข้อความ (เช่น ข้อความ LINE ลูกค้า) / อัปโหลด PDF, Excel, รูปถ่ายใบสั่งงาน / เลือกอีเมลจากกล่องรับงาน
- ผล: แบ่งจอซ้าย = ต้นฉบับ (ไฮไลต์ส่วนที่ถูกดึง), ขวา = ฟอร์ม SO ที่เติมแล้ว (ลูกค้าจับคู่กับข้อมูลหลัก, จุดรับ-ส่งจับคู่กับหน้าสถานที่, สินค้า/จำนวน/น้ำหนัก, วันเวลา, custom fields) — ช่องที่ AI ไม่มั่นใจขอบส้ม, ช่องที่หาไม่พบว่างพร้อมข้อความ "ไม่พบในต้นฉบับ"
- ข้อความเดียวมีหลายงาน → แสดงเป็น SO ร่างหลายใบ เลือกสร้างทีละใบหรือทั้งหมด
- กล่องรับงาน (inbox) ใหม่ใน ปฏิบัติการ: ข้อความที่เข้ามาจาก LINE OA / อีเมลรับงาน → สถานะ รอตรวจ / สร้าง SO แล้ว / ไม่ใช่งาน
- ตัวอย่างข้อมูล: ข้อความ LINE "พรุ่งนี้ 8 โมง รับปูน 24 ตัน ที่คลังอยุธยา ส่งโรงงานสระบุรี ขอรถพ่วง 1 คัน PO 45890"

== 2. อ่านเอกสาร (OCR) ==
- น้ำมันและค่าใช้จ่าย + ฟอร์ม M15 ในแอปคนขับ: ถ่าย/แนบใบเสร็จ → เติม วันที่ ปั๊ม ลิตร ราคา/ลิตร ยอด เลขผู้เสียภาษีผู้ขาย อัตโนมัติ (ร่าง)
- ใบสั่งซ่อม: แนบใบแจ้งหนี้อู่ → ร่างรายการอะไหล่/ค่าแรง
- เอกสารรถ: อัปโหลดกรมธรรม์/ภาษี/ตรอ. → เติมเลขที่ บริษัท วันเริ่ม-หมด เบี้ย
- แสดงรูปต้นฉบับข้างฟอร์มพร้อมกรอบตรงตำแหน่งที่อ่าน

== 3. ตรวจ POD ==
- drawer DO / แท็บ POD: ผลตรวจ AI เป็น checklist — รูปชัด ✓, มีลายเซ็น ✓, ชื่อผู้รับตรง ✓, จำนวนตรงกับ DO ⚠ (ใบส่งของเขียน 118 ถุง DO 120 ถุง), เห็นความเสียหาย ✗
- ผิดปกติ → ส่งเข้าศูนย์ข้อยกเว้นอัตโนมัติ (ประเภท "POD ไม่ครบ/ไม่ตรง") + ปุ่มขอ POD ใหม่จากคนขับ
- หน้าวางบิล: กรอง "POD ผ่าน AI แล้ว" เพื่อวางบิลได้ทันที

== 4. แนะนำการจับคู่ฟิลด์ (ต่อจากรอบ 12) ==
- หน้า Field mapping: หลังวางตัวอย่าง ปุ่ม "ให้ AI แนะนำ" → เติมการจับคู่ + การแปลงค่า + แนะนำ custom field ที่ควรสร้าง (ป้าย AI แนะนำ ทีละแถว ยอมรับทั้งหมด/ทีละแถว)

== 5. ถามข้อมูลด้วยภาษาพูด ==
- ช่องถามบนหัวหน้า (ต่อจากช่องค้นหา ⌘K: แท็บ "ถาม AI") หรือแผงด้านขวา
- ตัวอย่างคำถามแนะนำ: "กำไรลูกค้าสยามพลาสติกเดือนนี้", "รถคันไหนกินน้ำมันผิดปกติสัปดาห์นี้", "ลูกหนี้เกิน 60 วันมีใครบ้าง"
- คำตอบ: ข้อความสั้น + ตาราง/กราฟเล็ก + ลิงก์ "เปิดในรายงาน" + บอกช่วงข้อมูลและแหล่ง (เช่น "จากเที่ยวรถ 1–3 พ.ย. 2569, 42 เที่ยว") — อ่านอย่างเดียว ไม่แก้ข้อมูล
- เคารพสิทธิ์ผู้ใช้: ถามข้อมูลที่ไม่มีสิทธิ์ → ตอบว่าไม่มีสิทธิ์

== 6. ตั้งค่า → AI ==
- เปิด/ปิด AI ทั้งบริษัท และรายฟีเจอร์ (รับงาน, OCR, ตรวจ POD, จับคู่ฟิลด์, ถามข้อมูล)
- AI credit เดือนนี้: ใช้แล้ว / โควตาแพ็กเกจ (เริ่มต้น 200 / มาตรฐาน 1,000 / องค์กร ตกลง) + ปุ่มซื้อเพิ่ม (ลิงก์หน้าแพ็กเกจ) + แยกตามฟีเจอร์
- ความเป็นส่วนตัว: คำอธิบายว่าข้อมูลส่งไปประมวลผลที่ไหน, ไม่ใช้ข้อมูลฝึกโมเดล, ปิดบังเลขบัตร/เบอร์โทรก่อนส่ง (toggle)
- ประวัติ AI: ตาราง ฟีเจอร์ / เอกสาร / ผล (รับ แก้แล้วรับ ปฏิเสธ) / ผู้ยืนยัน / เวลา + อัตราความแม่น 30 วัน

== 7. ตั้งค่า → นักพัฒนา / Open API → แท็บใหม่ "MCP" (ออกแบบในแบบของเราเอง ใช้ pattern เดิมของ TMS — ไม่ลอกหน้าตาระบบอื่น) ==
หลัก: REST API, MCP, webhook และเอกสาร ใช้ schema ชุดเดียว (รวม custom fields ของ tenant) — เพิ่มฟิลด์ที่เดียวทุกที่อัปเดตตาม
- ส่วน "เชื่อมต่อ" (3 ขั้นในการ์ดเดียว): 1) Server URL เดียวทุกลูกค้า https://mcp.srithai-tms.co.th/v1 + ปุ่มคัดลอก (ไม่ใส่ company/user id ใน URL — ระบุจาก token) 2) แท็บตามโปรแกรม AI: Claude Code / Claude.ai / ChatGPT / อื่นๆ (JSON config) พร้อมคำสั่งคัดลอก 3) ครั้งแรกเข้าสู่ระบบ TMS แล้วกด "อนุญาต" (OAuth) — AI ได้ token โดยไม่เห็นรหัสผ่าน
- สิทธิ์ = สิทธิ์ของ role ผู้ใช้ ∩ scope ที่อนุญาตตอนเชื่อมต่อ (ไม่ใช่สิทธิ์ทั้งบริษัท) — แสดงคำอธิบายนี้ชัดในหน้า
- การเชื่อมต่อที่ใช้งานอยู่: ตาราง client, ผู้ใช้, scope, เชื่อมเมื่อ, ใช้ล่าสุด, จำนวนเรียก 7 วัน, ปุ่มเพิกถอน
- แคตตาล็อก tool: รายการซ้ายแบ่งหมวดงานขนส่ง (งานขนส่ง, ติดตาม/POD, วางแผน, จากเอกสาร/ข้อความ, บัญชี, รถ, ข้อมูลหลัก, รายงาน, ข้อยกเว้น) ตั้งชื่อ verb_entity เช่น create_order, search_orders, get_shipment_eta, get_pod, order_from_text, order_from_document, expense_from_receipt, create_invoices_from_delivered, list_overdue_receivables, list_expiring_documents, quote_rate, get_otif, list_exceptions
- หน้ารายละเอียด tool (drawer มาตรฐานของเรา): ชื่อ tool + ป้ายระดับ (อ่าน / ร่าง — ต้องยืนยันใน TMS / เขียน — ต้องยืนยันใน AI), scope ที่ต้องใช้, คำอธิบาย 2 บรรทัด, ตัวอย่างประโยคภาษาไทยแบบงานขนส่ง (เช่น "พรุ่งนี้รับปูน 24 ตันที่อยุธยาส่งสระบุรี ขอรถพ่วง 1 คัน"), ตารางพารามิเตอร์ (ใช้ตารางเดียวกับเอกสาร API รวม custom fields), ข้อควรรู้ (เช่น ลูกค้าเดิมบอกชื่อพอ, ระบบออกเลขเอกสารให้, ถ้าจับคู่สถานที่ไม่ได้ AI จะถามกลับ), เปิด/ปิด tool รายตัว, tool อื่นในหมวดเดียวกัน
- tool ที่กระทบเงิน ภาษี การจ่ายงานรถ หรือการลบ เป็นระดับ "ร่าง" เสมอ — ร่างไปอยู่ในกล่องรับงาน/รายการรอยืนยัน พร้อมป้าย "จาก MCP · ชื่อผู้ใช้"
- ภาพรวม Open API: แยกนับ REST กับ MCP และ อ่าน/สร้าง/แก้/อื่นๆ (การ์ด KPI + กราฟรายเดือน)
- log การเรียก tool รวมกับ Log การเรียก API (filter "MCP")
- เอกสาร REST API: แต่ละ endpoint ใช้แท็บ คำอธิบายข้อมูล / ตัวอย่างโค้ด / ลองเรียก (ลองเรียกได้เฉพาะ Sandbox เท่านั้น ห้ามยิงข้อมูลจริง); ตารางฟิลด์แบ่งกลุ่ม ข้อมูล / object / array และคอลัมน์ บังคับ ชนิด ความยาว คำอธิบายไทย ตัวอย่าง

== 8. เชื่อมกับส่วนอื่น ==
- หน้าแพ็กเกจลูกค้า (รอบ 13): แถบ "AI credit" ในการใช้งานเดือนนี้
- Platform Console: การใช้ AI ราย tenant (credit, ค่าใช้จ่าย), ปิด AI ราย tenant
