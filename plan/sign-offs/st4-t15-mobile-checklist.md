# ST4-T15 checklist ทดสอบหน้า public บนมือถือ (3 browser × 3 หน้า)

> งาน: `plan/01-phase0-backlog.md` ST4-T15 — "checklist ทดสอบ 3 browser × 3 หน้า ผ่านทุกช่อง หรือมี defect ที่ปิดแล้ว"
> รอบนี้ (25 พ.ย. 2569, lane mob, branch `qa/st4-t15-mobile-emulated`): **ทดสอบแบบจำลอง (emulation) ด้วย Playwright** เพราะยังไม่มีเครื่องจริง (PO: "ทำให้จบโดยไม่ต้องรอใคร")
> **ช่อง "เครื่องจริง" ยังว่าง — ต้องให้คนยืนยันรอบมือ ~5 นาทีต่อเครื่อง (§4)** · ST4-T15 จึงยังไม่ปิดจนกว่าช่องนั้นครบ

## 1. วิธีรัน (FACT)

```bash
npx playwright install webkit        # ครั้งแรก (chromium มีอยู่แล้ว)
pnpm e2e:mobile                      # = node e2e/prepare.mjs && playwright test -c playwright.mobile.config.ts
pnpm --filter @tms/web e2e:mobile --project=line-ios   # เฉพาะ project เดียว
```

- config: `apps/web/playwright.mobile.config.ts` · spec: `apps/web/e2e/mobile-public.spec.ts` (16 test = 4 project × 4 ขั้น)
- **[DECISION — lead 25 พ.ย. 2569, ย้อนได้]** เป็นสคริปต์ opt-in แยก (แบบ `e2e:a11y` ของ ST9-T20) ไม่อยู่ใน `pnpm e2e` / `ci:local`: ต้องติดตั้ง webkit เพิ่ม และสร้างข้อมูลใหม่ทุก project (~1.5–2.5 นาที) — `playwright.config.ts` ตั้ง `testIgnore` ไว้ E2E หลักจึงไม่ช้าลง · E2E หลักยังครอบ flow เดียวกันที่ 390 px ใน chromium (`subcon-offer-link`, `subcon-link-pod`, `tracking-link`)
- ระหว่างรันปิดคำขอออกนอกเครื่องทั้งหมด (Google Fonts ฯลฯ) — ภาพจึงเป็นฟอนต์สำรองของระบบ ไม่ใช่ IBM Plex Sans Thai Looped (ตรวจฟอนต์จริงในรอบมือ)

| project | engine | UA / จอ (CSS px) | แทน |

| `android-chrome` | chromium | Pixel 7 (Android 14, Chrome) · 390 × 839 · DPR 2.625 · touch | Chrome Android |
| `ios-safari` | webkit | iPhone 14 (Safari) · 390 × 664 (หักแถบ Safari) · DPR 3 · touch | Safari iOS |

**[DECISION — lead 25 พ.ย. 2569, ย้อนได้]** ทุก project กว้าง 390 px (มาตรฐานภาพเทียบหน้า public — CLAUDE.md) และตรวจซ้ำที่ 360 px · ความสูง LINE เป็นค่าประมาณ (แถบหัวชื่อ+URL และแถบเครื่องมือล่างของ LINE)

## 2. สิ่งที่ตรวจต่อหน้า (ทุก project)

1. ไม่มี scroll แนวนอนที่ 390 px **และ** 360 px (`scrollWidth ≤ clientWidth`)
2. ข้อความไทยอยู่บนหน้า และไม่มี key i18n หลุด (เช่น `pdl.pod.add`)
3. เป้ากด: ปุ่ม/ช่องกรอกทุกตัว ≥ 24 px (WCAG 2.2 SC 2.5.8 AA) = เกณฑ์ตก · < 44 px บันทึกเป็นข้อสังเกตใน `st4-t15/<project>.json` — **[DECISION — lead 25 พ.ย. 2569, ย้อนได้]** docs/04 "touch target ≥ 48 px / ปุ่มหลัก 56 px" เป็นข้อของแอปคนขับ (P1) หน้า public ยึดขนาดต้นแบบ TMS Subcon / TMS Tracking
4. การกระทำหลักด้วยการแตะ (`tap()` — touch event) และผลลัพธ์ฝั่งระบบผ่าน `/v1`:
   - **ข้อเสนองาน:** ปฏิเสธ + เลือกเหตุผล → "ปฏิเสธ" · เที่ยวกลับ PLANNING · รับงาน + กรอกทะเบียน/ชื่อ/เบอร์ → "รับงาน" · เที่ยว ASSIGNED
   - **POD:** ค้นเลข DO → ถึงจุดรับ → ออกจากจุดรับ → ถึงจุดส่ง → แนบรูป 2 ใบผ่าน file input → **เซ็นด้วยนิ้ว** (chromium: touch จริงของ CDP · webkit: PointerEvent ชนิด touch) ตรวจว่ามีเส้นบน canvas + `touch-action: none` (หน้าไม่เลื่อนตามนิ้ว) → ส่ง POD → DO = UNBILLED
   - **tracking:** ลิงก์ของลูกค้า ค้นเลข PO + เบอร์ 4 ตัวท้าย → "ส่งแล้ว" ไม่มีราคา · ลิงก์ต่อ DO → "ส่งแล้ว" + การ์ดหลักฐานการส่ง
5. ภาพหน้าจอเต็มหน้า (JPEG, 1 CSS px = 1 px) ที่ `plan/sign-offs/st4-t15/<project>-<หน้า>.jpg`

## 6. สิ่งที่การจำลองยืนยันไม่ได้ (จึงอยู่ในรอบมือ §4)

- กล้อง/ตัวเลือกรูปของระบบ (file input ทดสอบด้วยไฟล์ที่ใส่ตรง) · การหมุนรูปตาม EXIF
- ฟอนต์จาก Google Fonts บนเครือข่ายมือถือ (การรันปิดคำขอภายนอก)
- การซูมตอนแตะช่องกรอกของ iOS (D2) · แป้นพิมพ์บังปุ่ม · แถบเครื่องมือ LINE ที่หด/ขยายตามการเลื่อน
- ท่าทาง touch จริงบน Safari (webkit ใช้ PointerEvent สังเคราะห์ — chromium ใช้ touch จริงของ CDP)
- ลิงก์ `tel:` เปิดแอปโทรศัพท์ · การเปิดลิงก์จากแชต LINE (in-app browser จริง ไม่ใช่แค่ UA)
