## 2. ข้อสรุป

- **ด้านความปลอดภัย:** ตรง docs/04 B/J และ NFR-304 เกือบครบ — เข้ารหัส, ไม่คืนเลขเต็มใน API/audit/export/log, ดูเต็มต้องมีสิทธิ์ + เหตุผล + audit · ต่างจาก docs/spec ที่ **key อยู่ใน env ไม่ใช่ KMS และไม่มี data key ต่อ tenant** (รอเลือก cloud — ST0-T01)
- **ข้อขัดกันเอกสาร vs โค้ด:** spec/11 §4.2 ระบุเลขบัตรของ "คนขับ/รถร่วมบุคคล" ใช้ทำ 50 ทวิ/ภ.ง.ด.3 แต่โค้ดออก 50 ทวิจากเลขรถร่วมเท่านั้น — บันทึกใน spec/12 §3 แล้ว (รอ PO/ทนาย LEG-5)
- **ด้านหลักการเก็บเท่าที่จำเป็น (minimization):** ไม่บังคับกรอก (ตรง NFR-303) แต่**ยังไม่มีวัตถุประสงค์ที่ระบบใช้ค่านี้จริง** (F-11) — ถ้าเก็บโดยไม่มีวัตถุประสงค์ที่แจ้งไว้ อาจขัดหลักเก็บเท่าที่จำเป็น **[ต้องให้ทนายตรวจ LEG-5]**
- **ช่องโหว่ที่ชัด:** ไฟล์นำเข้าต้นฉบับเก็บเลขเต็มไม่มีกำหนด (F-9) และทุก role/API key อ่านได้ถ้ารู้ id (F-7)
- **ความต่างของสิทธิ์:** spec/02 MD-202 ให้เห็นเลขบัตร/ใบขับขี่เฉพาะ `driver.pii.view` แต่โค้ดให้ทุก `master:read` เห็น 4 หลักท้ายและเลขใบขับขี่เต็ม; สิทธิ์ดูเลขเต็มใช้ `users:write` แทน (บันทึกเป็น [OPEN spec/12 §3] ไว้แล้วตั้งแต่ ST2-T08 — `drivers.service.ts:52`)
