# 00 — เอกสารไหนใช้ตัดสินเรื่องอะไร

> ร่าง 10 พ.ย. 2569 · ไฟล์นี้สั้นโดยตั้งใจ รายละเอียดการเทียบอยู่ใน `00a-reconcile-architecture.md` (431 บรรทัด) และ `00b-reconcile-requirements.md` (583 บรรทัด)

## 1. ทำไมต้องมีไฟล์นี้

โปรเจกต์มีเอกสาร 2 ชุดที่เขียนแยกกันและซ้อนทับกัน:

| ชุด | เขียนเมื่อ | โดย | จุดแข็ง | จุดอ่อน |
|---|---|---|---|---|
| `docs/` (v2) | 3–4 พ.ย. 2569 | เจ้าของสินค้า | สถาปัตยกรรม, data model, state machine, มาตรฐาน API, KRS connector, ลำดับ P0–P2 ที่ผูกกับ roadmap ขาย, รายการ "สิ่งที่ไม่ทำ" | ยังไม่มีสิ่งที่ออกแบบหลัง 4 พ.ย. (fleet ส่วนขยาย, custom fields, Open API UI, MCP, AI, one-platform, landing) |
| `spec/` | 9 พ.ย. 2569 | เขียนจาก research + ดีไซน์ 18 รอบ **โดยไม่ได้อ่าน `docs/`** | รายละเอียดระดับหน้าจอ/ฟิลด์/เกณฑ์ตรวจรับ, โมดูลใหม่, รวมคำถามค้าง | โครงข้อมูล ชื่อ และสถานะไม่ตรง docs; เฟส P0 กว้างกว่า docs มาก; ขัดกันเองระหว่างไฟล์บางจุด |

ผลการเทียบ: **ตรงกันในระดับหลักการ แต่ต่างกันมากในระดับ schema ชื่อ สถานะ และลำดับเฟส** — เขียนโค้ดจากสองชุดพร้อมกันไม่ได้

## 2. กติกา (เสนอ — รอยืนยันใน `05-decisions-needed.md` D-01)

## 3. ความต่างที่กระทบแผนมากที่สุด

| เรื่อง | docs v2 | spec | แผนนี้ใช้ |
|---|---|---|---|
| ความหมายของ "P0" | ต้องมีเพื่อขาย standalone รายแรก + ขึ้น KRS pilot | MVP ที่กว้างกว่า (≈ เฟสขาย 0 + 1 + บางส่วนของ 2) | docs |
| แอปคนขับ | เฟส 0 แค่ลิงก์เว็บรถร่วม; แอปเฟสขาย 2 | แอป M1–M18 อยู่ใน MVP | docs (D-03) |
| KRS connector | เฟส 0 | connector ตัวแรก P1 ยังไม่เลือก | docs (D-04 รอยืนยัน) |
| Open API | UI ใช้ `/v1` ตั้งแต่วันแรก; API + webhook เป็น P0 | Open API เป็นฟีเจอร์ P1 | docs สำหรับแกน; ส่วนสาธารณะเลื่อน (D-05) |
| สมัครเอง / แพ็กเกจ / Console | เฟสขาย 1; เฟส 0 แค่ admin portal ขั้นต่ำ | MVP | docs (D-06) |
| กฎตอนจัดรถ | เตือน + override พร้อมเหตุผล | บล็อก + ผู้จัดการอนุมัติ | รอเลือก (D-07) |
| Fleet เฟสแรก | ทะเบียน + เอกสาร | + ใบสั่งซ่อม, น้ำมัน, อุบัติเหตุ, ผลตรวจรถ | docs (D-08) |
| เอกสารขาย | ตารางแยกตามประเภท | ตารางเดียวแยกด้วยประเภท | docs |
| ชื่อ | `company`, `carrier`, `delivery-orders`, enum ตัวใหญ่ใน DB | `LegalEntity`, `Subcontractor`, `shipments`, enum ตัวเล็ก | docs (D-17, D-26) |
| ราคาแพ็กเกจ | 350/280/220 ตามขนาด fleet | 249/399/499 ตามฟีเจอร์ (ต้นแบบ ฿390/฿690) | ยังไม่ต้องเคาะในเฟส 0 (D-40) |

## 4. สิ่งที่ต้องทำกับเอกสาร (งานใน ST0)

1. เจ้าของตอบ `05-decisions-needed.md` กลุ่ม A
2. แก้ `spec/` ตาม checklist ใน `00a` §3 และ `00b` — อย่างน้อยให้ติดป้ายหัวไฟล์ทุกไฟล์ว่า "เมื่อขัดกับ docs v2 ให้ยึด docs" จนกว่าจะแก้เนื้อหาครบ (ติดป้ายแล้ว 10 พ.ย. — ดู `spec/README.md`)
3. เพิ่มสิ่งที่ spec มีและควรอยู่ใน docs v2 ตาม `00a` §4 (เช่น ตารางที่ docs อ้างถึงแต่ยังไม่นิยาม: `document`, `cash_advance`, `vendor`)
4. แก้จุดที่ docs ขัดกันเอง: สถานะ invoice ใน diagram §4.4, GPS connector (docs/04 P1 ↔ docs/02 เฟส 3), settlement dispute (docs/04 P0 ↔ docs/02 เฟส 3)
5. หลัง ST0 ให้มีเอกสารอ้างอิงชุดเดียวต่อเรื่อง — ไม่เก็บสองฉบับที่พูดเรื่องเดียวกัน
