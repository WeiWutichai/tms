# 09 — แผนนำร่องและขึ้นใช้งานจริง เฟส 0

> ร่าง 10 พ.ย. 2569 · อ้างอิง `docs/02` §7 (เกณฑ์ผ่านเฟส 0), `docs/01` Appendix A (KRS), `03-test-plan.md`

## 1. ผู้ร่วมนำร่อง 2 กลุ่ม

| | กลุ่ม 1: KRS (มี ERP) | กลุ่ม 2: Standalone (ไม่มี ERP) |
|---|---|---|
| ใคร | ลูกค้า KRS 1 tenant | บริษัทขนส่งใกล้ตัว 1–2 ราย ใช้ฟรี — **ยังไม่ได้ระบุชื่อ** (docs/02 §8) |
| พิสูจน์อะไร | connector framework ใช้ได้จริง; ยอดสองระบบตรงกัน | ออกเอกสารภาษีไทยครบชุดได้เองโดยไม่มี ERP |
| เกณฑ์ผ่าน | ปิดงวด 2 เดือนติดกัน MISMATCH ค้าง = 0 | ออกใบกำกับภาษี + 50 ทวิ ครบ 1 รอบเดือน และนักบัญชีของเขายอมรับ |
| ต้องมีก่อนเริ่ม | คำตอบใน `08-questions-krs.md`, contract + ช่องทดสอบ, ข้อตกลง SLA นำร่อง | นักบัญชีของลูกค้ายินดีตรวจเอกสาร, ข้อมูลหลักเป็น Excel |
| เริ่มได้เมื่อ | ST8 เสร็จ + UAT กลุ่ม KRS ผ่าน | ST6 เสร็จ + UAT บัญชีผ่าน (ไม่ต้องรอ ST8) |

กลุ่ม 2 เริ่มได้ก่อนกลุ่ม 1 — แนะนำให้ขึ้นกลุ่ม 2 ทันทีที่ ST6 + ส่วนจำเป็นของ ST9 ผ่าน เพื่อเริ่มนับรอบเดือนเร็วที่สุด

## 2. ขั้นตอนต่อ tenant

| ขั้น | ทำอะไร | ใครทำ | ผลลัพธ์ |
|---|---|---|---|
| 1. เตรียม (−2 สัปดาห์) | ประชุมเปิด, กำหนดผู้ประสานงาน, เก็บตัวอย่างเอกสารจริง (ใบวางบิล, ใบกำกับ, 50 ทวิ, ใบคุมรถ), รายการรถ/ลูกค้า/รถร่วม/ราคา | เรา + ลูกค้า | รายการข้อมูลที่ต้องนำเข้า; ความต่างของรูปแบบเอกสาร |
| 2. ตั้งค่า (−1 สัปดาห์) | สร้าง tenant, นิติบุคคล/สาขา, เลขเอกสาร (เริ่มเลขต่อจากเล่มเดิมหรือ series ใหม่ — ให้นักบัญชีเลือก), ภาษี, ผู้ใช้/สิทธิ์ | เรา | tenant พร้อม |
| 3. นำเข้าข้อมูล | Excel dry-run → แก้แถวผิด → commit: ลูกค้า, จุดส่ง, รถ, คนขับ, รถร่วม, rate card | ลูกค้า (เราช่วย) | ข้อมูลหลักครบ |
| 4. ซ้อม (3–5 วัน) | ทำงานจริงคู่ขนานกับวิธีเดิม 1 สัปดาห์สั้น: รับงาน → จัดรถ → POD → วางบิลทดลอง (ไม่ส่งลูกค้า) | ลูกค้า | รายการปัญหา |
| 5. ตัดระบบ | กำหนดวันเริ่ม (แนะนำวันแรกของงวดบัญชี); KRS: ตั้ง `syncFromDate` = วันเริ่ม; งานค้างจากระบบเดิมไม่ย้าย ยกเว้นยอดลูกหนี้ยกมา (ถ้าต้องการ aging ครบ) | เรา + ลูกค้า | ใช้งานจริง |
| 6. ประคอง (4 สัปดาห์แรก) | ช่องทางแจ้งปัญหาตรง, ตอบภายใน 4 ชม.ทำการ, ประชุมสั้นทุกสัปดาห์ | เรา | บันทึกปัญหา + แก้ |
| 7. ปิดงวด | สิ้นเดือน: รายงานภาษีขาย, 50 ทวิ, settlement; KRS: reconcile ทุกใบ → MISMATCH = 0 | บัญชีลูกค้า + เรา | แบบเซ็นรับรายเดือน |

## 3. รายการตรวจก่อนขึ้นใช้งานจริง

- [ ] เกณฑ์ go-live ใน `03-test-plan.md` §6 ผ่านครบ
- [ ] นักบัญชีของลูกค้าเซ็นรับรูปแบบเอกสาร 6 ชนิด + 50 ทวิ จากตัวอย่างจริงของเขา
- [ ] เลขเอกสารเริ่มต้นตั้งถูกทุก series (ทดสอบออก 1 ใบใน tenant ทดสอบที่คัดลอกค่า)
- [ ] ผู้ใช้ทุกคนเข้าได้ + 2FA สำหรับ owner/บัญชีที่อนุมัติ
- [ ] backup อัตโนมัติทำงาน + ซ้อมกู้แล้ว
- [ ] monitoring + แจ้งเตือนเมื่อ error rate สูง / outbox ค้าง / connector ล้มเหลว
- [ ] runbook 4 เรื่อง (ระบบล่ม, connector ล้ม, เลขเอกสารผิด, ขอลบข้อมูล)
- [ ] เอกสารสัญญา/ความยินยอม: เงื่อนไขนำร่อง, นโยบายความเป็นส่วนตัว, ข้อตกลงประมวลผลข้อมูล (ตามคำตอบทนาย)
- [ ] KRS เพิ่ม: credential production, `syncFromDate`, mapping รหัสสินค้า/บริการครบ, ใครเป็นเจ้าของเอกสารภาษี (`taxDocumentOwner`) ตั้งแล้ว

## 4. ตัวชี้วัดช่วงนำร่อง

| ตัวชี้วัด | เป้า | วัดจาก |
|---|---|---|
| MISMATCH ค้างสิ้นงวด (KRS) | 0 | หน้า reconcile |
| เอกสารภาษีที่นักบัญชีตีกลับ | 0 หลังเดือนแรก | แบบเซ็นรับ |
| งานที่ปิดด้วย ePOD ผ่านลิงก์ (รถร่วม) | ≥ 80% ของงานรถร่วม | ระบบ |
| เวลาจากส่งของถึงวางบิล | ลดลงเทียบก่อนใช้ (เก็บค่าฐานในขั้นเตรียม) | ระบบ + สัมภาษณ์ |
| ปัญหาระดับ "ขวางงาน" | 0 ค้างเกิน 1 วันทำการ | บันทึกปัญหา |
| ต้องใช้ Excel ช่วยนอกระบบ | ไม่มีในเดือนที่ 2 | สัมภาษณ์ |

## 5. แผนถอย

- 2 สัปดาห์แรกทำงานคู่ขนานในส่วนเอกสารภาษี: ถ้าระบบออกเอกสารผิด ลูกค้าออกด้วยวิธีเดิมได้ทันที และเราแก้ + ออกใบแทน/ใบลดหนี้ตามกฎ
- KRS: ปิด connector ได้โดย TMS ยังทำงาน standalone (หลัก standalone-first) แล้ว export ไฟล์ให้บัญชีคีย์เอง จนกว่าจะแก้เสร็จ
- ข้อมูล: export ทุกตารางหลักเป็น Excel ได้ตลอดช่วงนำร่อง
