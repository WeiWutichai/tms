## 1. FLT-A ทะเบียนรถและโปรไฟล์รถ

**1. จุดประสงค์** — ทะเบียนรถทุกคัน (บริษัท + รถร่วม) เป็นแหล่งเดียวของข้อมูลรถ ต้นทุน และความพร้อมใช้งาน

**2. ผู้ใช้/สิทธิ์** — fleet (สร้าง/แก้), manager (ทุกอย่าง + ข้อมูลการเงินรถ), dispatcher (ดู + เปลี่ยนคนขับประจำ), accounting (ดูข้อมูลการเงิน) · สิทธิ์ `vehicle.view|create|edit|delete|export`, `vehicle.finance.view` (ราคาซื้อ ค่าเสื่อม กำไร — field-level P3)

**3. หน้าจอ**
- **ทะเบียนรถ**: แถบสรุปบรรทัดเดียว (ทั้งหมด · พร้อมใช้ · ซ่อม · จอด · ติดกฎห้ามจ่ายงาน · เอกสารใกล้หมด 30 วัน); แท็บ ทั้งหมด / รถบริษัท / รถร่วม / ซ่อม-จอด / จำหน่ายแล้ว; ตาราง: ทะเบียน ("71-0457 กทม." น้ำหนัก 500) · ประเภทรถ · ยี่ห้อ/รุ่น · คนขับประจำ · สถานะ · เลขไมล์ · เอกสารใกล้หมด (ป้ายวันที่ใกล้สุด) · km/L 30 วัน · ต้นทุน/กม. 30 วัน; ปุ่ม "+ เพิ่มรถ", "นำเข้า Excel" (dry-run ก่อนบันทึก — P8)
- **โปรไฟล์รถ** (หน้าเต็ม): หัว ทะเบียน + ประเภท + สถานะ + ป้ายติดกฎ (ถ้ามี, ปุ่ม "ดูสาเหตุ"); KPI 4 ใบ: km/L (30 วัน) · ต้นทุน/กม. (เดือนนี้) · อัตราการใช้รถ % (เดือนนี้) · กำไรเดือนนี้ (เฉพาะ `vehicle.finance.view`); แท็บ: **ข้อมูล** · **เอกสาร** · **ซ่อมบำรุง** (WO + PM) · **น้ำมัน** · **ต้นทุน** (แยกหมวดรายเดือน) · **ยาง** (ผัง) · **ลีสซิ่ง** · **เลขไมล์** · **ประวัติ** (เที่ยว, การพ่วงหาง, เปลี่ยนคนขับ, อุบัติเหตุ, ค่าปรับ, audit)

**5. กฎธุรกิจ**
- **FLT-001** ทะเบียนซ้ำ (ทะเบียน + จังหวัด) ห้ามสร้างใหม่ เว้นแต่คันเดิม `retired`
- **FLT-002** เปลี่ยนประเภทรถได้ถ้าไม่มีเที่ยว `dispatched/in_progress`; เปลี่ยนแล้วผังยาง (FLT-G) ที่ตำแหน่งไม่ตรงต้องถอดก่อน
- **FLT-003** ต้นทุน/กม. (ช่วงเวลา) = (น้ำมัน + ใบสั่งซ่อมที่ปิด + ยาง (ตามต้นทุน/กม. ของยางที่ติด) + อะไหล่ที่เบิกเข้า WO (ถ้าไม่อยู่ใน WO แล้ว) + เอกสาร (ประกัน/พ.ร.บ./ภาษี/ตรอ. เฉลี่ยรายวันตามช่วงคุ้มครอง) + ลีสซิ่ง/เช่าซื้อ **หรือ** ค่าเสื่อม (เลือกโหมดตาม FLT-262) + ค่าปรับที่บริษัทจ่าย + ค่าเคลมส่วนที่บริษัทรับ) ÷ กม.ในช่วง (FLT-O); ไม่รวมค่าแรงคนขับ (อยู่ในต้นทุนเที่ยว 05) [PROPOSED]
- **FLT-004** ค่าเสื่อม (มุมมองบริหาร ไม่ใช่บัญชี): straight-line รายเดือน = (purchasePrice − salvageValue) ÷ usefulLifeMonths; bookValue = purchasePrice − ค่าเสื่อมสะสมถึงสิ้นเดือนก่อน (ไม่ต่ำกว่า salvage); ถ้าเชื่อมระบบบัญชี ตัวเลขทางบัญชีอยู่ใน ERP — หน้านี้ระบุ "ตัวเลขเพื่อการบริหาร"
- **FLT-005** อัตราการใช้รถ % (เดือน) = วันที่มีเที่ยว `in_progress` อย่างน้อย 1 ครั้ง ÷ วันที่รถอยู่ในสถานะ `active` (ไม่นับวัน `in_repair/parked`) × 100
- **FLT-006** กำไรรายเดือนต่อรถ = รายได้ที่ปันส่วนให้รถจากบรรทัดใบแจ้งหนี้/DO ที่ส่งแล้ว (PL10, กฎ X3: ใช้ ledger เดียวกับบิล) − ต้นทุนเที่ยว (ค่าเที่ยวคนขับ, ค่าใช้จ่ายเที่ยว) − ต้นทุนรถ (FLT-003 × กม.); รถร่วม: รายได้ − ค่าจ้างรถร่วม (ไม่มีต้นทุนรถ)
- **FLT-007** km/L = ลิตรแบบ full-to-full (FLT-I) — แสดง "—" ถ้าข้อมูล < 2 ครั้งเติมเต็ม
- **FLT-008** ลบรถได้เฉพาะที่ไม่เคยมีเที่ยว/ค่าใช้จ่าย; นอกนั้นใช้ "จำหน่าย" (soft — D7)
- **FLT-009** รถร่วม `unverified` จ่ายงานได้ (เพื่อไม่ให้งานหยุด) แต่ติดป้าย "ยังไม่ตรวจ" และ fleet ได้งานในรายการ "รถร่วมรอตรวจ" (FLT-P)

**6. สถานะ — `Vehicle.status`**
| จาก → ไป | เงื่อนไข | ใครทำ | ผลข้างเคียง |
|---|---|---|---|
| (สร้าง) → `active` | ข้อมูลบังคับครบ | fleet | |
| `active` → `in_repair` | WO เปลี่ยนเป็น "กำลังซ่อม" และติ๊ก "รถใช้งานไม่ได้" หรือ fleet ตั้งเอง | ระบบ/fleet | เหตุห้ามจ่ายงาน `VEHICLE_UNDER_REPAIR`; งานที่จ่ายไว้แล้วติดป้าย "ต้องย้ายรถ" (03) |
| `in_repair` → `active` | WO ทุกใบที่ทำให้ใช้งานไม่ได้ "เสร็จ" แล้ว | ระบบ/fleet | |
| `active` ↔ `parked` | จอดพัก (ไม่มีคนขับ/รองาน/ระงับ) เหตุผลบังคับ | fleet, manager | `VEHICLE_PARKED` |
| ใด ๆ → `retired` | ขาย/ตัดจำหน่าย: วันที่, ราคาขาย, เหตุผล; ไม่มีเที่ยวค้าง | manager | ปิดเอกสาร/แจ้งเตือน/PM; ถอดยางทั้งหมดเป็น "ไม่ทราบ" หรือย้ายคลัง |

**7. Event** — `vehicle.created`, `vehicle.updated`, `vehicle.status_changed`, `vehicle.retired` (webhook: `vehicle.*` scope `vehicles:read`)

**8. กรณีผิดปกติ** — นำเข้า Excel ทะเบียนซ้ำ → แถว error ใน dry-run · เปลี่ยนสถานะเป็นซ่อมขณะรถวิ่ง → อนุญาต (รถเสียกลางทาง) แต่เที่ยวที่วิ่งอยู่ไม่ถูกยกเลิกเอง · รถร่วมชื่อซ้ำทะเบียนกับรถบริษัท → error (ต้องตรวจทะเบียน)

**9. เกณฑ์ตรวจรับ**
- Given รถซื้อ 2,400,000.00 อายุ 120 เดือน ซาก 400,000.00 Then ค่าเสื่อม 16,666.67/เดือน และ bookValue ลดตามเดือน
- Given รถ `in_repair` Then กระดานวางแผนแสดงแถวรถเป็นลาย hatch + ป้าย "ซ่อม"
- Given ผู้ใช้ไม่มี `vehicle.finance.view` Then ไม่เห็นราคาซื้อและ KPI กำไร (ทั้ง UI และ API)

**10. เฟส** — P0 (KPI ต้นทุน/กม. และกำไร P1 เมื่อข้อมูลต้นทุนครบ)

## 2. FLT-B หางพ่วง/หางลาก (ทรัพย์สินแยก)

**1. จุดประสงค์** — หางมีทะเบียน เอกสาร PM ยาง ของตัวเอง และประวัติการพ่วงกับหัวลาก

**2. ผู้ใช้/สิทธิ์** — fleet, dispatcher (พ่วง/ปลดในเที่ยว) · `trailer.*`

**3. หน้าจอ** — เมนู "หาง" (โครงเดียวกับทะเบียนรถ, แท็บ ข้อมูล/เอกสาร/ซ่อมบำรุง/ยาง/ประวัติการพ่วง); ในโปรไฟล์หัวลากแท็บประวัติแสดงหางที่พ่วง; ปุ่ม "พ่วงหาง"/"ปลดหาง"

**4. ฟิลด์ — `Trailer`** (ใช้ตาราง Vehicle เดียวกันด้วย `assetKind = trailer` [PROPOSED] เพื่อใช้เอกสาร/WO/ยางร่วม): plateNo/Province ✓, trailerType (`semi_trailer|full_trailer|flatbed|container_chassis|tanker|reefer`), axleCount ✓ (1–4), payloadKg ✓, ownership, carrierId · **`CouplingRecord`**: tractorId ✓, trailerId ✓, coupledAt ✓, uncoupledAt, coupledBy, source (`manual|trip`), tripId, odometerAtCouple

**5. กฎธุรกิจ**
- **FLT-020** หาง 1 ตัวพ่วงได้ 1 หัวในเวลาเดียว; หัว 1 คันพ่วงหางได้ ≤ จำนวนตามประเภทรถ (ปกติ 1; รถพ่วง 10 ล้อ + หางพ่วง 1)
- **FLT-021** การกำหนดหางในเที่ยว (03) สร้าง CouplingRecord อัตโนมัติเมื่อเที่ยว `in_progress` ถ้าหัวยังไม่พ่วงหางนั้น และปิด record เดิมของหัว/หาง
- **FLT-022** ความจุรวมของเที่ยว = min(payload ของหัวตามประเภท, payload หาง) ตามกฎน้ำหนักใน 03 — ค่าน้ำหนักตามกฎหมายต่อประเภทรถอยู่ที่ 02/03
- **FLT-023** เอกสารหางหมด/หางซ่อม → เหตุห้ามจ่ายงานของเที่ยวที่ใช้หางนั้น (`TRAILER_*`)
- **FLT-024** กม.ของหางคิดจากกม.ของหัวลากระหว่างช่วงพ่วง (ใช้กับ PM และยางของหาง)

**6. สถานะ** — เหมือน FLT-A + สถานะการพ่วง `coupled|uncoupled` (คำนวณจาก CouplingRecord ที่ยังไม่ปิด)

**7. Event** — `trailer.coupled`, `trailer.uncoupled`

**8. กรณีผิดปกติ** — พ่วงหางที่พ่วงกับหัวอื่นอยู่ → dialog "หางนี้พ่วงกับ 70-1234 อยู่ ปลดแล้วพ่วงใหม่?" · บันทึกย้อนหลังทับช่วงเวลาที่มี record แล้ว → ไม่อนุญาต

**9. เกณฑ์ตรวจรับ** — Given หาง T1 พ่วงกับหัว A When เที่ยวใหม่ใช้ T1 กับหัว B เริ่มวิ่ง Then record A–T1 ถูกปิด และมี record B–T1 ใหม่ · Given หัววิ่ง 1,000 กม. ขณะพ่วง T1 Then กม. T1 เพิ่ม 1,000

**10. เฟส** — P0

## 3. FLT-C เอกสารรถ และแจ้งเตือนใกล้หมดอายุ

**1. จุดประสงค์** — เก็บเอกสารตามกฎหมายและสัญญาของรถ/หาง พร้อมแจ้งเตือนก่อนหมด และป้อนเหตุห้ามจ่ายงาน

**2. ผู้ใช้/สิทธิ์** — fleet (สร้าง/แก้), ผู้รับผิดชอบรายประเภทเอกสาร (รับแจ้งเตือน), manager · `vehicle_document.*`

## 4. FLT-D แผนซ่อมบำรุงตามระยะ (PM) และปฏิทิน

**1. จุดประสงค์** — กำหนดรอบเปลี่ยนถ่าย/ตรวจเช็กตามกม. หรือวัน ต่อประเภทรถ แล้วแสดงรายการครบกำหนดและปฏิทิน

**2. ผู้ใช้/สิทธิ์** — fleet (ตั้งแผน, สร้าง WO), manager · `pm.*`

**3. หน้าจอ**
- **แผน PM** (ตั้งค่า fleet): ต่อประเภทรถ/หาง: รายการงาน (เปลี่ยนน้ำมันเครื่อง, กรองโซลาร์, จาระบี, ตรวจเบรก, ตั้งศูนย์ ฯลฯ) + รอบ ทุก X กม. และ/หรือ ทุก Y วัน (อันไหนถึงก่อน) + เตือนล่วงหน้า (กม./วัน) + ค่าใช้จ่ายประมาณ + อู่เริ่มต้น; override ต่อคันได้
- **รายการครบกำหนด**: แท็บ เลยกำหนด / ครบใน 7 วัน (หรือ ≤ 1,000 กม.) / ใกล้ครบ / ทั้งหมด; ตาราง: ทะเบียน · งาน PM · ครบที่ (กม./วัน) · เหลือ · ทำล่าสุด; ปุ่ม "สร้างใบสั่งซ่อม" (เลือกหลายรายการของรถเดียวกันรวมเป็น 1 WO)
- **ปฏิทิน**: เดือน/สัปดาห์ แสดง PM ที่คาดว่าจะครบ (คาดจากกม.เฉลี่ยต่อวันของรถ 30 วัน) + WO ที่นัดไว้; ลากเลื่อนวันนัด WO ได้; แสดงเที่ยวที่จ่ายไว้แล้วของรถนั้นเพื่อเลี่ยงชน

- **FLT-084** สร้างจากข้อบกพร่องตรวจรถ (FLT-F) หรือ M6: เติม assetId, symptom (ชื่อข้อ + หมายเหตุคนขับ), รูป, reportedBy = คนขับ, source + ลิงก์กลับ; defect เปลี่ยนเป็น `wo_opened`
- **FLT-085** OCR ใบแจ้งหนี้อู่ (08) → ร่างบรรทัดอะไหล่/ค่าแรง ให้ผู้ใช้ยืนยัน
- **FLT-086** ปิด WO → ต้นทุนเข้าต้นทุนรถ (FLT-003), PM schedule อัปเดต (FLT-061), defect ที่ผูก → `fixed`, รถกลับ `active` ถ้าไม่มี WO อื่นที่ทำให้ใช้งานไม่ได้
- **FLT-087** การบันทึกเจ้าหนี้อู่/จ่ายเงินอู่: TMS ส่ง WO ที่ปิดเป็น "ค่าใช้จ่ายรอบันทึก" ให้บัญชี (export/connector) — TMS จะทำ AP ผู้ขายเต็มรูป (ตั้งหนี้ จ่าย หัก ณ ที่จ่ายค่าซ่อม 3%) หรือไม่ → [OPEN] FLT-Q2
- **FLT-088** WO แก้ไขไม่ได้หลัง `closed`; แก้ด้วยการ "เปิดใหม่" (manager, เหตุผล) ภายในเดือนเดียวกัน

**6. สถานะ**
| จาก → ไป | เงื่อนไข | ใครทำ | ผลข้างเคียง |
|---|---|---|---|
| (สร้าง) → `reported` แจ้งเสีย | symptom + asset | fleet/คนขับ/ระบบ | `work_order.created` |
| `reported` → `pending_approval` รออนุมัติ | estimatedTotal + (vendor ถ้าซ่อมนอก) | fleet | แจ้งผู้อนุมัติ |
| `pending_approval` → `approved` (ภายใน) → `in_progress` กำลังซ่อม | ผู้อนุมัติวงเงินพอ → กด "เริ่มซ่อม" | ผู้อนุมัติ / fleet | `makesVehicleUnavailable` → รถ `in_repair` |

**7. Event** — `work_order.created`, `work_order.submitted`, `work_order.approved`, `work_order.rejected`, `work_order.started`, `work_order.completed`, `work_order.closed`, `work_order.cancelled`

**8. กรณีผิดปกติ** — ผู้อนุมัติไม่อยู่ > 24 ชม. → แจ้งขั้นถัดไป (ตั้งค่าได้) · รถเสียกลางทาง (ซ่อมด่วน) → "ซ่อมฉุกเฉิน" ข้ามการอนุมัติก่อนเริ่ม แต่ต้องอนุมัติย้อนหลังก่อนปิด (ป้าย "อนุมัติย้อนหลัง") · ลบบรรทัดอะไหล่ที่เบิกจากสต็อก → คืนสต็อก (FLT-H)

**9. เกณฑ์ตรวจรับ**
- Given วงเงิน หัวหน้าช่าง 5,000 / ผู้จัดการ 50,000 When WO ประมาณการ 12,000.00 Then ผู้อนุมัติคือผู้จัดการ และหัวหน้าช่างกดอนุมัติไม่ได้
- Given อนุมัติ 12,000 ยอดจริง 14,500 Then ต้องอนุมัติเพิ่มก่อนปิด
- Given WO ซ่อมนอกไม่มีไฟล์ใบเสร็จ When กดปิด Then error "ต้องแนบใบเสร็จ/ใบแจ้งหนี้อู่"
- Given defect "ไฟเบรกไม่ติด" มีรูป 2 รูป When กด "เปิดใบสั่งซ่อม" Then WO ใหม่มีอาการ รูป ทะเบียน และคนแจ้งครบ

**10. เฟส** — P0 (OCR ใบแจ้งหนี้อู่ P1)

**2. ผู้ใช้/สิทธิ์** — fleet, dispatcher (ดู), manager (override) · `inspection.view|record_on_behalf|override`, `defect.manage`

**3. หน้าจอ**

- แท็บ **ผลตรวจวันนี้** (เลือกวันได้): ทะเบียน · คนขับ · เวลา · ผล (ผ่าน/มีข้อบกพร่อง/ไม่ผ่าน) · จำนวนข้อบกพร่อง · รูป (thumbnail) · บันทึกโดย (คนขับ/บันทึกแทน)
- แท็บ **ข้อบกพร่องค้าง**: ทะเบียน · ข้อ · วิกฤต · หมายเหตุ · รูป · พบเมื่อ · อายุ (วัน) · สถานะ · ปุ่ม "เปิดใบสั่งซ่อม" (เลือกหลายข้อของรถเดียวกันรวม 1 WO) / "ไม่ต้องซ่อม" (เหตุผล)

- **FLT-104** รูปตรวจรถเก็บตามนโยบาย retention ของรูป (11) ค่าเริ่มต้น 1 ปี [PROPOSED]

- **FLT-124** การติด/ถอด/สลับ บันทึก odometer ของรถ ณ เวลานั้น (ค่าเริ่มต้นจาก FLT-O ล่าสุด) เพื่อคำนวณกม.ต่อเส้น
- **FLT-125** ยางที่ซื้อผ่าน WO (บรรทัดชนิด part + tyreId) ไม่นับต้นทุนซ้ำ: ต้นทุนยางเข้ารถผ่านต้นทุน/กม. ของยาง ไม่ใช่ผ่าน WO (WO line ติดธง `capitalised_tyre`)

**6. สถานะ** — `in_stock → mounted (mount) → in_stock (dismount) → retreading (retread_send) → in_stock (retread_return, retreadCount+1, initialTread ใหม่) → scrapped`

**7. Event** — `tyre.mounted`, `tyre.dismounted`, `tyre.low_tread`, `tyre.scrapped`

**9. เกณฑ์ตรวจรับ** — Given ยาง 12,000.00 วิ่ง 60,000 กม. Then ต้นทุน 0.20/กม. · Given วัดดอก 2.5 มม. เกณฑ์ 3.0 Then ตำแหน่งเป็นสีแดงและแจ้ง fleet · Given ลากสลับยาง L1 ↔ R1 Then มี event rotate 2 รายการพร้อมเลขไมล์

**10. เฟส** — P1

**3. หน้าจอ** — รายการอะไหล่ (KPI: รายการ · ต่ำกว่าจุดสั่งซื้อ · มูลค่าคงคลัง); ตาราง: รหัส · ชื่อ · หมวด · หน่วย · คงเหลือ · จุดสั่งซื้อ · ต้นทุนเฉลี่ย · มูลค่า; drawer: แท็บ ความเคลื่อนไหว / ใช้กับรถประเภท; ฟอร์ม รับเข้า (หลายบรรทัด, ผู้ขาย, เลขที่ใบเสร็จ/ใบกำกับ, ไฟล์), ปรับยอด (นับจริง + เหตุผล); การเบิกทำจากบรรทัด WO

**4. ฟิลด์ — `Part` / `StockMovement`**

**6. สถานะ** — สัญญา: `active → completed | terminated (ปิดก่อนกำหนด, เหตุผล)`; งวด: `scheduled → due (≤ 7 วัน) → paid | overdue → paid`

**7. Event** — `lease.installment_due`, `lease.installment_overdue`, `lease.completed`

**8. กรณีผิดปกติ** — ขายรถขณะสัญญา active → บังคับปิดสัญญา (terminated) ก่อน `retired` · จ่ายหลายงวดพร้อมกัน → เลือกหลายงวดบันทึกครั้งเดียว

**9. เกณฑ์ตรวจรับ** — Given สัญญา 48 งวด งวดละ 35,000 วันที่ 5 เริ่ม ม.ค. Then มี 48 งวด และ 29 ม.ค. แจ้ง "ครบ 5 ก.พ." · Given โหมดเงินสด Then ต้นทุนเดือนรวม 35,000 (ก่อน VAT ตาม FLT-263) และไม่รวมค่าเสื่อม

**10. เฟส** — P1

## 15. FLT-O ประวัติเลขไมล์

**1. จุดประสงค์** — เลขไมล์ที่เชื่อถือได้หนึ่งชุดต่อรถ สำหรับ PM ต้นทุน/กม. km/L ยาง และตรวจความผิดปกติ

**2. ผู้ใช้/สิทธิ์** — fleet (แก้มือ), ระบบ · `odometer.view|edit`

**3. หน้าจอ** — แท็บ "เลขไมล์" ในโปรไฟล์รถ: กราฟเลขไมล์ตามเวลา + ตาราง: วันเวลา · ค่า · แหล่ง · Δ จากครั้งก่อน · ธง · ผู้แก้/เหตุผล; ปุ่ม "บันทึกเลขไมล์" / "เปลี่ยนเรือนไมล์"; หน้ารวม "เลขไมล์ผิดปกติ" (รายการธงรอตรวจทุกรถ)

**5. กฎธุรกิจ**
- **FLT-280** ค่า "ไมล์ปัจจุบัน" ของรถ = reading `accepted` ล่าสุดตาม readAt (รวม offset) — ใช้ทุกโมดูล
- **FLT-281** GPS: บันทึกวันละ 1 ค่า (ค่าสุดท้ายของวัน) จาก GPS provider ที่ส่ง odometer หรือคำนวณระยะสะสมจากตำแหน่ง (ติดป้าย "คำนวณ") — P1
- **FLT-282** **ถอยหลัง**: readingKm < ค่าปัจจุบัน → `backwards` → สถานะ `flagged`; จากแอปคนขับ (M7/M16/M15) ถูกปฏิเสธที่หน้าแอปก่อน (04); จากแหล่งอื่น → รอ fleet ตัดสิน (accept พร้อมเหตุผล `meter_replaced` / reject)
- **FLT-283** **กระโดด**: Δกม. > max(1,200 กม./วัน × จำนวนวันที่ผ่านไป, ความเร็วเฉลี่ย 110 กม./ชม. × ชม.ที่ผ่านไป) → `jump` `flagged` [PROPOSED]
- **FLT-284** `gps_mismatch`: ระยะเที่ยวจากไมล์ (M16) ต่างจากระยะ GPS > 15% (04 DRV-211)
- **FLT-285** แก้ด้วยมือ: ไม่แก้ทับค่าเดิม — สร้าง reading ใหม่ `manual` ที่อ้าง `originalReadingId` และตั้งค่าเดิมเป็น `superseded`; บังคับ editReasonType (+ note) และบันทึก audit
- **FLT-286** เปลี่ยนเรือนไมล์: บันทึกค่าเรือนเก่าสุดท้าย + ค่าเรือนใหม่เริ่มต้น → offset = เก่า − ใหม่; ไมล์สะสมต่อเนื่อง
- **FLT-287** reading ที่ `flagged` ไม่ถูกใช้เป็นไมล์ปัจจุบันจนกว่าจะ accept

**6. สถานะ** — `accepted` / `flagged → accepted | rejected` / `accepted → superseded` (มีการแก้)

**7. Event** — `odometer.recorded`, `odometer.flagged`, `odometer.corrected`

**8. กรณีผิดปกติ** — reading มาช้า (ออฟไลน์) ที่ readAt เก่ากว่าค่าล่าสุด → เปรียบเทียบกับค่าก่อน/หลังตามเวลา ไม่ใช่ค่าล่าสุดเสมอ · สองแหล่งเวลาเดียวกันต่างกัน > 50 กม. → ใช้ค่าคน (pretrip/trip_end) ถ้า GPS เป็นระยะคำนวณ

**9. เกณฑ์ตรวจรับ** — Given ไมล์ปัจจุบัน 150,000 When GPS ส่ง 149,500 Then flagged และไมล์ปัจจุบันยัง 150,000 · Given แก้มือโดยไม่เลือกเหตุผล Then บันทึกไม่ได้ · Given เปลี่ยนเรือนไมล์ เก่า 250,000 ใหม่ 0 แล้ววิ่ง 100 Then ไมล์สะสม 250,100

**10. เฟส** — P0 (แอป/มือ/WO/น้ำมัน) · P1 (GPS)
