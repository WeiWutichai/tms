## 1. ภาพรวม (Dashboard)

1. **จุดประสงค์** — หน้าแรกหลัง login บอกสถานะงานวันนี้และเงินค้าง ภายใน 5 วินาที
2. **ผู้ใช้/สิทธิ์** — ทุก role ภายในบริษัท (ยกเว้น driver/subcontractor/shipper); การ์ดเงินแสดงเฉพาะผู้มี `report.finance:view` (RPT-011)
3. **หน้าจอ** — แถว KPI 4 ใบ (คลิกกรอง) → กราฟความสำเร็จ 7 วัน → การ์ดสรุปลูกหนี้ → รายการต้องจัดการวันนี้ (ข้อยกเว้นเปิด, เอกสารรถใกล้หมด, เงินเบิกค้างเคลียร์); การ์ด "คิวเชื่อมระบบบัญชี" แสดงเฉพาะเมื่อมี connector; setup checklist อยู่ใน 01-platform
4. **ฟิลด์ (นิยาม KPI)**

| KPI | สูตร | หมายเหตุ / คลิกไป |
|---|---|---|
| งานวันนี้ | `count(DO)` ที่ `plannedDeliveryDate = today` และ status ≠ CANCELLED; บรรทัดรอง "ส่งแล้ว x / y" โดย x = status ∈ {DELIVERED, PARTIALLY_DELIVERED} | รายการ DO วันนี้ |
| รอจัดรถ | `count(SO/DO)` ที่ status = รอวางแผน (ยังไม่อยู่ในเที่ยว) และ `plannedPickupDate ≤ today + 1`; บรรทัดรอง "เลยกำหนดรับ n" (pickupDate < today) สีแดง | กระดานวางแผน คอลัมน์ "SO รอจัด" |
| กำลังวิ่ง | `count(Trip)` status = IN_PROGRESS; บรรทัดรอง "ล่าช้า n" = เที่ยวที่มี stop ถัดไป ETA > windowEnd | หน้าติดตามรถ |
| ใบแจ้งหนี้เกินกำหนด | `count` และ `Σ outstanding` ของ INV status = OVERDUE (BIL-040) | หน้าใบแจ้งหนี้ แท็บเกินกำหนด |
| กราฟสำเร็จ 7 วัน | ต่อวัน d ∈ [today−6, today]: แท่งซ้อน สำเร็จ / บางส่วน / ไม่สำเร็จ / ยังเปิด ของ DO ที่ `plannedDeliveryDate = d`; เส้น `success% = DELIVERED / (ทั้งหมดของวัน d − CANCELLED)` | DO ของวันนั้น |
| ลูกหนี้คงค้าง | `Σ outstanding` (BIL-120) ทุก INV/DN ที่ค้าง | AR aging |
| เกินกำหนด | `Σ outstanding` ที่ `dueDate < today` | AR aging (กรองเกินกำหนด) |
| ครบกำหนด 7 วันข้างหน้า | `Σ outstanding` ที่ `today ≤ dueDate ≤ today+7` | |
| รับชำระเดือนนี้ | `Σ (cashAmount + whtAmount + bankFee)` ของ Payment POSTED ที่ receivedDate อยู่ในเดือนปัจจุบัน | หน้ารับชำระ |
| การ์ดบิล (R2) | จำนวน/ยอด: พร้อมวางบิล · ร่าง · ออกแล้วรอชำระ · ชำระบางส่วน | หน้าวางบิล |

5. **กฎธุรกิจ**
- **RPT-011** ผู้ไม่มีสิทธิ์การเงินเห็นเฉพาะ KPI ปฏิบัติการ (งานวันนี้ · รอจัดรถ · กำลังวิ่ง · กราฟ 7 วัน) — การ์ดเงินไม่ render (ไม่ใช่แค่ซ่อนด้วย CSS) และ API ไม่ส่งค่า

## 2. กำไรต่อเที่ยว / ลูกค้า / รถ (R1)

1. **จุดประสงค์** — รู้ว่าเที่ยว ลูกค้า และรถคันไหนทำกำไร
2. **ผู้ใช้/สิทธิ์** — owner, manager, accounting (`report.profit:view`)
3. **หน้าจอ** — รายงาน > กำไร: แท็บ ต่อเที่ยว · ต่อลูกค้า · ต่อรถ · ต่อเส้นทาง; ตาราง + กราฟแท่ง top/bottom 10; drawer เที่ยว = waterfall รายได้ → ต้นทุนแต่ละหมวด → กำไร; ป้าย "ประมาณการ" เมื่อต้นทุน/รายได้ยังไม่ปิด
4. **ฟิลด์ (นิยาม)**

| ตัวแปร | สูตร | แหล่ง |
|---|---|---|
| `Rev(trip)` | Σ amount ของ revenue line ทุก DO ในเที่ยว (ก่อน VAT) − Σ ACN/CN ที่อ้างบรรทัดเหล่านั้น + Σ ADN/DN | DO revenue line / InvoiceLine (sourceLineId เดียวกัน, B1) |
| `C_fuel` | Σ ExpenseEntry FUEL ที่ผูก tripId (ก่อน VAT) + ส่วนแบ่งน้ำมันที่ไม่ผูกเที่ยว = `fuelUnlinked(vehicle, month) × km(trip) / km(vehicle, month)` | 05 §12, 06 น้ำมัน/ถังน้ำมัน |
| `C_toll` | Σ ExpenseEntry TOLL ที่ผูก tripId | |
| `C_driver` | Σ DriverEarning (ค่าเที่ยว เบี้ยเลี้ยง OT) ที่ผูก tripId | 05 §13 |
| `C_subcon` | Σ SettlementLine EARNING ของเที่ยว (ก่อน VAT, ก่อนหัก WHT/รายการหัก); ถ้ายังไม่มี settlement ใช้ cost line ประมาณการจาก rate card รถร่วม | 05 §11 |
| `C_other` | Σ expense อื่นที่ผูกเที่ยว (ค่าขึ้นลง จอด ฯลฯ) | |
| `C_maint` | `(WO cost + tyre cost)(vehicle, month) × km(trip) / km(vehicle, month)` — [PROPOSED] วิธีแบ่งตาม กม.; [OPEN] RQ1 | 06 |
| `Cost(trip)` | C_fuel + C_toll + C_driver + C_subcon + C_other + C_maint | |
| `GP(trip)` | Rev − Cost | กำไรขั้นต้นต่อเที่ยว (ไม่รวมต้นทุนคงที่) |
| `GP%` | GP / Rev × 100 (Rev = 0 → "—") | |
| `Rev(customer)` | Σ revenue line ของ DO ลูกค้านั้นในงวด | |
| `Cost(customer)` | Σ_trip Cost(trip) × share(customer, trip); `share` = สัดส่วนรายได้ของลูกค้าในเที่ยว (ค่าเริ่มต้น) หรือ น้ำหนัก หรือ จำนวน DO (ตั้งค่า) [PROPOSED] | |
| `GP(vehicle)` | Σ GP(trip) ของรถ − `FixedCost(vehicle, period)` | |
| `FixedCost(vehicle)` | ค่างวดลีสซิ่ง + ประกัน/พ.ร.บ./ภาษีรถ (เฉลี่ยรายเดือนตามอายุกรมธรรม์) + เงินเดือนคนขับประจำรถ [OPEN] RQ2 + ค่าเสื่อม [OPEN] RQ5 | 06 |

5. **กฎธุรกิจ**
- **RPT-020** งวดของเที่ยว = วันที่เที่ยว COMPLETED (ฐานงาน) เป็นค่าเริ่มต้น; ตัวเลือก "ตามวันที่ใบแจ้งหนี้" — [OPEN] RQ6
- **RPT-021** เที่ยวที่ยังไม่มีเอกสารจริง (ยังไม่วางบิล/ยังไม่ settlement/ค่าใช้จ่ายรออนุมัติ) แสดงป้าย "ประมาณการ" และนับยอดประมาณการแยกคอลัมน์
- **RPT-022** เที่ยวที่รายได้ = 0 (วิ่งเปล่า/ตีรถกลับ) ไม่ถูกแบ่งให้ลูกค้า แสดงในแถว "เที่ยวเปล่า" ของรายงานลูกค้า และยังนับใน GP(vehicle)
- **RPT-023** เที่ยวรถร่วมไม่มี C_fuel/C_maint ของบริษัท (ยกเว้นน้ำมันที่บริษัทเติมให้ ซึ่งหักใน settlement แล้ว → ไม่นับซ้ำ)
- **RPT-024** รายการหักคนขับ/รถร่วม (ค่าปรับ อุบัติเหตุ) ไม่ลดต้นทุนเที่ยว; แสดงในรายงานค่าปรับ (§8) แยก
- **RPT-025** GP% ติดลบหรือต่ำกว่าเป้า (ตั้งค่า, ค่าเริ่มต้น 10%) เน้นสีแดง
6. **สถานะ** — ไม่มี
7. **event** — ไม่มี
8. **กรณีผิดปกติ** — km(vehicle, month) = 0 แต่มีค่าซ่อม → C_maint ไม่แบ่ง แสดงในแถว "ต้นทุนรถที่ยังไม่ได้แบ่ง"; เลขไมล์ผิดปกติ (06) → ใช้ระยะตามแผนของเที่ยวแทนและติดป้าย
9. **เกณฑ์ตรวจรับ**
   - Given เที่ยว T1 รายได้ 12,000.00 น้ำมันผูกเที่ยว 3,500.00 ทางด่วน 300.00 ค่าเที่ยวคนขับ 600.00 รถวิ่งเดือนนี้ 5,000 กม. ค่าซ่อม+ยางเดือนนี้ 10,000.00 T1 วิ่ง 250 กม. · Then C_maint = 500.00, Cost = 4,900.00, GP = 7,100.00, GP% = 59.2
   - Given เที่ยว T2 มี DO ลูกค้า A 6,000.00 และ B 2,000.00 Cost 4,000.00 share=รายได้ · Then Cost(A) = 3,000.00, Cost(B) = 1,000.00
   - Given เที่ยวรถร่วม T3 รายได้ 10,000.00 settlement 8,000.00 WHT 80.00 · Then C_subcon = 8,000.00 GP = 2,000.00 (WHT ไม่นับ)
10. **เฟส** — P1 (ต่อเที่ยว/ลูกค้า/รถ); P2 (ตัวเลือกการแบ่งต้นทุนขั้นสูง)

## 3. ลูกหนี้ (AR aging)

1. **จุดประสงค์** — เห็นยอดค้างตามอายุ ตามลูกค้า และติดตามการเก็บเงิน
2. **ผู้ใช้/สิทธิ์** — owner, manager, accounting
3. **หน้าจอ** — ตารางลูกค้า × ช่วงอายุ + รวม; การ์ด DSO, ระยะเวลารับชำระเฉลี่ย, 50 ทวิ ค้างรับ; ปุ่มส่ง statement (BIL-123); ประวัติ snapshot สิ้นเดือน
4. **ฟิลด์ (นิยาม)**

| ตัวชี้วัด | สูตร |
|---|---|
| outstanding ต่อเอกสาร | ตาม BIL-120 |
| `daysPastDue` | `asOfDate − dueDate` (≤ 0 = ยังไม่ครบกำหนด) |
| ช่วงอายุ (ค่าเริ่มต้น) | ยังไม่ครบกำหนด · 1–30 · 31–60 · 61–90 · > 90 วัน (ตั้งช่วงเองได้); ตัวเลือก "นับจากวันที่เอกสาร" แทน dueDate |
| เครดิตลูกค้า | unapplied + CN ที่ยังไม่ตัด แสดงเป็นแถวติดลบแยก ไม่หักกลบในช่วงอายุ |
| DSO (90 วัน) | `AR_outstanding(asOf) / Σ grandTotal ของ INV ที่ออกใน 90 วันก่อน asOf × 90` |
| ระยะเวลารับชำระเฉลี่ย | `Σ (receivedDate − invoiceIssueDate) × applied / Σ applied` ของ allocation ในงวด |
| 50 ทวิ ค้างรับ | count/Σ whtAmount ของ payment ที่ whtCert.status = PENDING (BIL-057) |

5. **กฎธุรกิจ**
- **RPT-030** `asOfDate` เลือกย้อนหลังได้: คำนวณจากเอกสาร/payment ที่มีวันที่ ≤ asOfDate และสถานะ ณ วันนั้น (ยกเลิกหลัง asOfDate ถือว่ายัง active)
- **RPT-031** snapshot สิ้นเดือนเก็บอัตโนมัติ 00:30 วันที่ 1 เพื่อเปรียบเทียบเดือนต่อเดือน
- **RPT-032** ผลรวมทุกช่วงอายุ = ลูกหนี้คงค้างบน dashboard (RPT-001)
6–7. — ไม่มีสถานะ/event (การแจ้งเตือนหนี้อยู่ใน BIL-121)
8. **กรณีผิดปกติ** — INV ที่ dueDate รอคำนวณจากใบวางบิล (BIL-031) → ใช้ dueDate ชั่วคราวและติดป้าย
9. **เกณฑ์ตรวจรับ**
   - Given asOf 9 พ.ย. 2569: INV-1 due 20 พ.ย. ค้าง 10,000; INV-2 due 1 ต.ค. ค้าง 5,000; INV-3 due 1 ก.ค. ค้าง 2,000 · Then ยังไม่ครบกำหนด 10,000 · 31–60 = 5,000 · > 90 = 2,000 (131 วัน) · รวม 17,000
   - Given ลูกค้าจ่ายเกิน 1,000 (unapplied) · Then แถวเครดิต −1,000 แยก และช่วงอายุไม่ถูกหัก
10. **เฟส** — P0 (aging, snapshot); P1 (DSO, ระยะเวลารับชำระเฉลี่ย)

2. **ผู้ใช้/สิทธิ์** — owner, manager, accounting; dispatcher เห็นเฉพาะจำนวนเที่ยว/อัตรา (ไม่มีกำไร) ถ้าได้ `report.subcon:view`
3. **หน้าจอ** — แท็บ AP aging · ต้นทุนรถร่วม · ยังไม่เข้า settlement
4. **ฟิลด์ (นิยาม)**

| ตัวชี้วัด | สูตร |
|---|---|
| AP outstanding ต่อ settlement | `netPayable − Σ PV.amount` ของ settlement สถานะ APPROVED/PARTIALLY_PAID |
| `daysPastDue` (AP) | `asOfDate − settlement.dueDate`; ช่วงอายุเหมือน §3 |
| งานรถร่วมยังไม่เข้า settlement (ค้างตั้งหนี้) | Σ cost line ประมาณการของเที่ยวรถร่วม COMPLETED ที่ไม่อยู่ใน settlement active; แยกอายุจากวันจบเที่ยว |
| ต้นทุนรถร่วมต่อราย | จำนวนเที่ยว, Σ gross, Σ รายการหัก, Σ WHT, Σ สุทธิ, ต้นทุนเฉลี่ยต่อเที่ยว |
| สัดส่วนต้นทุน/รายได้ | `Σ C_subcon / Σ Rev(trip)` ของเที่ยวรถร่วมนั้น × 100 |
| อัตราโต้แย้ง | `count(settlement ที่เคย DISPUTED) / count(settlement ที่ส่งตรวจ)` |
| เทียบรถบริษัท | ต้นทุนต่อเที่ยวรถร่วม vs Cost(trip) รถบริษัทในเส้นทาง+ประเภทรถเดียวกัน |

5. **กฎธุรกิจ**
- **RPT-040** AP aging คิดเฉพาะ settlement ที่ APPROVED ขึ้นไป; DRAFT/SENT/DISPUTED/CONFIRMED แสดงในหัวข้อ "รออนุมัติ" แยก
- **RPT-041** ยอดค้างจ่ายติดลบ (ยอดหักยกไป) แสดงเป็นแถวลูกหนี้รถร่วมแยก
6–7. — ไม่มี
8. **กรณีผิดปกติ** — เที่ยวรถร่วมไม่มีราคาใน rate card → นับใน "ค้างตั้งหนี้" ยอด 0 และติดป้าย "ไม่มีราคา"
9. **เกณฑ์ตรวจรับ** — Given SET-1 อนุมัติ net 10,865.00 due 15 ต.ค. จ่ายแล้ว 5,000.00 · When asOf 9 พ.ย. 2569 · Then ค้าง 5,865.00 ช่วง 1–30 (25 วัน)

## 5. OTIF (On-Time In-Full)

1. **จุดประสงค์** — วัดคุณภาพการส่งต่อลูกค้า/เส้นทาง/ประเภทรถ/รถร่วม และใช้ส่งรายงานให้ลูกค้า
2. **ผู้ใช้/สิทธิ์** — manager, dispatcher, accounting (`report.ops:view`); รายงานส่งลูกค้าใช้ `report.ops:share`
3. **หน้าจอ** — การ์ด OTIF% · OT% · IF% (เทียบงวดก่อน) → ตารางตามมิติ (ลูกค้า · เส้นทาง · ประเภทรถ · รถบริษัท/รถร่วม · คนขับ · รถร่วม) → กราฟแนวโน้มรายสัปดาห์ → รายการ DO ที่ไม่ผ่าน พร้อมเหตุผล
4. **ฟิลด์ (นิยาม)**

| คำ | นิยาม |
|---|---|
| หน่วยวัด | DO (1 จุดส่ง) |
| DO ที่นับ (eligible) | DO ที่ `plannedDeliveryDate` อยู่ในงวด และสถานะสุดท้าย ∈ {DELIVERED, PARTIALLY_DELIVERED, FAILED}; ไม่นับ CANCELLED; ไม่นับ DO ที่ยังเปิด |
| หน้าต่างสัญญา (`promisedWindow`) | ช่วงเวลาส่งที่ตกลงกับลูกค้า ณ ตอนยืนยันจ่ายงาน; เปลี่ยนได้เฉพาะเมื่อลูกค้าขอ (เหตุ `CUSTOMER_REQUEST`) — การเลื่อนโดยฝั่งเราไม่เปลี่ยน baseline; ถ้ามีแค่วันที่ → windowEnd = 23:59:59 ของวันนั้น |
| เวลาส่งจริง (`actualTime`) | ตามตั้งค่า `otBasis`: `ARRIVAL` (เข้า geofence ปลายทางหรือคนขับกด "ถึงแล้ว" — ใช้ค่าที่เกิดก่อน) ค่าเริ่มต้น หรือ `POD_TIME` (เวลาบันทึก POD) [PROPOSED] — [OPEN] RQ3 |
| On-time (OT) | `actualTime ≤ windowEnd + lateTolerance` (ค่าเริ่มต้น 0 นาที, ตั้งต่อลูกค้า) และถ้าลูกค้าตั้ง "ห้ามส่งก่อน" ต้อง `actualTime ≥ windowStart − earlyTolerance`; FAILED = ไม่ OT |
| In-full (IF) | ทุกบรรทัดสินค้า: `deliveredQty ≥ orderedQty × (1 − qtyTolerance%)` (ค่าเริ่มต้น 0%) และ `rejectedQty = 0` และ `damagedQty = 0`; PARTIALLY_DELIVERED หรือ FAILED = ไม่ IF |
| OT% | count(OT) / count(eligible) × 100 |
| IF% | count(IF) / count(eligible) × 100 |
| OTIF% | count(OT ∧ IF) / count(eligible) × 100 |
| เส้นทาง | คู่ (สถานที่/จังหวัดต้นทาง → ปลายทาง) หรือรหัสเส้นทางใน rate card (เลือกมิติได้) |

5. **กฎธุรกิจ**
- **RPT-050** ตัวเลือก `excludeCustomerCaused` (ค่าเริ่มต้น **ปิด**): ถ้าเปิด DO ที่ล้มเหลว/ล่าช้าด้วยเหตุที่ระบุเป็นความรับผิดชอบลูกค้า (ปลายทางปิด ไม่มีคนรับ ลูกค้าเลื่อน) ไม่นับเป็น eligible; รายงานต้องแสดงจำนวนที่ถูกตัดออกเสมอ [PROPOSED] — [OPEN] RQ3
- **RPT-051** เหตุผลล่าช้า/ไม่ครบมาจาก exception (04-execution) และ M13 (ส่งไม่สำเร็จ/ส่งบางส่วน); DO ที่ไม่ผ่านแต่ไม่มีเหตุผล แสดงในแท็บ "ไม่มีเหตุผล" ให้ dispatcher เติม
- **RPT-052** ปรับ `promisedWindow` ย้อนหลังหลังส่งแล้วไม่ได้ (กันแต่งตัวเลข); แก้ได้เฉพาะ manager พร้อมเหตุผลและ audit
- **RPT-053** รายงาน OTIF ส่งลูกค้า (R3) แสดงเฉพาะ DO ของลูกค้านั้น ไม่มีชื่อคนขับเต็ม (PDPA — แสดงชื่อย่อหรือทะเบียนเท่านั้น) [PROPOSED]
6–7. — ไม่มี
8. **กรณีผิดปกติ** — DO ไม่มีเวลาเข้า geofence (GPS หาย) และ otBasis=ARRIVAL → ใช้เวลา POD แทนและติดป้าย "ใช้เวลา POD"; DO หลาย stop ในเที่ยวเดียวคิดแยกต่อ DO
9. **เกณฑ์ตรวจรับ**
   - Given DO window 08:00–12:00 ถึง 12:10 tolerance 0 · Then ไม่ OT; tolerance 15 นาที · Then OT
   - Given DO สั่ง 100 ถุง ส่ง 98 ถุง qtyTolerance 0% · Then ไม่ IF; qtyTolerance 5% · Then IF
   - Given 10 DO: 8 OT∧IF, 1 OT แต่ไม่ IF, 1 FAILED · Then OT% 90.0, IF% 80.0, OTIF% 80.0
   - Given ลูกค้าขอเลื่อนจากวันที่ 5 เป็น 6 และส่งวันที่ 6 · Then OT (baseline เปลี่ยนตามคำขอลูกค้า)
10. **เฟส** — P1

## 6. POD ครบ %

1. **จุดประสงค์** — วัดความครบของหลักฐานส่งมอบ ซึ่งเป็นเงื่อนไขวางบิล (BIL-020)
2. **ผู้ใช้/สิทธิ์** — manager, dispatcher, accounting
3. **หน้าจอ** — การ์ด POD ครบ % · ครบภายใน 24 ชม. % · AI ตั้งข้อสังเกต % · เวลาเฉลี่ยส่งถึงพร้อมวางบิล; ตารางตามลูกค้า/คนขับ/รถร่วม; รายการ DO ที่ POD ยังไม่ครบ
4. **ฟิลด์ (นิยาม)**

| ตัวชี้วัด | สูตร |
|---|---|
| eligible | DO สถานะ DELIVERED หรือ PARTIALLY_DELIVERED ที่ deliveredAt อยู่ในงวด |
| POD ครบ | มีองค์ประกอบครบตาม `podRequirement` ของลูกค้า (ลายเซ็น, ชื่อผู้รับ, รูป ≥ n, รูปใบส่งของกระดาษ, พิกัดใน geofence, เวลา) **และ** podStatus ∈ {AI_PASSED, VERIFIED} |
| POD ครบ % | count(POD ครบ) / count(eligible) × 100 |
| POD ครบภายใน 24 ชม. % | count(POD ครบ และ `podCompletedAt − deliveredAt ≤ 24 ชม.`) / count(eligible) × 100 |
| AI ตั้งข้อสังเกต % | count(เคยเป็น AI_FLAGGED) / count(POD ที่ส่งตรวจ AI) × 100 |
| เวลาเฉลี่ยถึงพร้อมวางบิล | mean(`readyToBillAt − deliveredAt`) เป็นชั่วโมง ของ DO ที่ READY ในงวด |

5. **กฎธุรกิจ** — **RPT-060** POD ที่ถูก REJECTED แล้วอัปโหลดใหม่ใช้ `podCompletedAt` ของครั้งที่ผ่าน; **RPT-061** รายการค้างเรียงตามอายุ และส่งเตือนคนขับ/รถร่วมได้จากหน้านี้ (04-execution)
6–7. — ไม่มี
8. **กรณีผิดปกติ** — ลูกค้าไม่มี podRequirement → ใช้ค่ากลางของ tenant
9. **เกณฑ์ตรวจรับ** — Given 50 DO ส่งแล้ว, 45 POD ครบ (40 ภายใน 24 ชม.) · Then POD ครบ 90.0%, ภายใน 24 ชม. 80.0%
10. **เฟส** — P1

## 7. ภาษี: สรุปหัก ณ ที่จ่ายรายเดือน และสรุป VAT

1. **จุดประสงค์** — ให้บัญชีเตรียมยื่นแบบรายเดือนและติดตาม 50 ทวิ ทั้งสองฝั่ง (ไฟล์ส่งออกอยู่ใน 05-billing §14)
2. **ผู้ใช้/สิทธิ์** — owner, accounting (`report.tax:view`)
3. **หน้าจอ** — เลือกเดือนภาษี + นิติบุคคล/สาขา → 3 การ์ด: WHT ฝั่งจ่าย · WHT ฝั่งรับ · VAT; แต่ละการ์ดมีปุ่มดาวน์โหลดไฟล์ที่เกี่ยวข้องและวันครบกำหนดยื่น
4. **ฟิลด์ (นิยาม)**

| ส่วน | ตัวชี้วัด |
|---|---|
| WHT ฝั่งจ่าย | แยก ภ.ง.ด.3 / ภ.ง.ด.53 [FACT TAX §3.1]: จำนวนผู้ถูกหัก, จำนวนรายการ, Σ เงินได้, Σ ภาษีที่หัก (จาก WhtEntry PAID ที่ `paidDate` ในเดือน), 50 ทวิ ที่ออกแล้ว/ยังไม่ออก, ผู้ถูกหักที่ไม่มีเลขผู้เสียภาษี |
| WHT ฝั่งรับ | Σ whtExpected ของ INV ที่รับชำระในเดือน vs Σ whtAmount ที่ลูกค้าหักจริง, ผลต่าง, 50 ทวิ ได้รับ/ค้างรับ (BIL-057) |
| VAT | ภาษีขาย: Σ vatBase/vatAmount ของ RT − CN + DN ที่ issueDate ในเดือน (แยกสาขา [FACT TAX §5.2]); ยอดขายที่ได้รับยกเว้น (Σ RC ส่วนยกเว้น) [PROPOSED]; ภาษีซื้อ: Σ จากรายงานภาษีซื้อ (BIL §14) |
| กำหนดยื่น | ภ.ง.ด.3/53: กระดาษวันที่ 7 เดือนถัดไป, อินเทอร์เน็ตถึงวันที่ 15 [FACT TAX §3.1]; ภ.พ.30: กระดาษวันที่ 15 [FACT TAX §3.1] (วันออนไลน์ดูปฏิทินกรมสรรพากรรายเดือน) |

5. **กฎธุรกิจ**
- **RPT-070** ตัวเลขในหน้านี้ต้องเท่ากับผลรวมของไฟล์ส่งออกเดือนเดียวกัน (BIL-170)

6–7. — event `tax_summary.reminder_sent`

## 8. รายงาน fleet

1. **จุดประสงค์** — ต้นทุนและความพร้อมของรถบริษัท (design-briefs รอบ 6 ข้อ 15)
2. **ผู้ใช้/สิทธิ์** — fleet, manager, owner (`report.fleet:view`); ค่าปรับต่อคนขับต้องมี `report.driver:view` (ข้อมูลบุคคล)
3. **หน้าจอ** — รายงาน > Fleet: แท็บ ต้นทุน/กม. · อัตรากินน้ำมัน · Downtime · PM ตรงเวลา · TCO · ยาง · ค่าปรับต่อคนขับ; ทุกแท็บมีมุมมองรายคันและรายประเภทรถ
4. **ฟิลด์ (นิยาม)**

| ตัวชี้วัด | สูตร |
|---|---|
| `km(v, P)` | เลขไมล์สุดท้ายในงวด − เลขไมล์สุดท้ายก่อนงวด (ประวัติเลขไมล์ 06; ค่าที่ถูกตรวจว่าผิดปกติและยังไม่แก้ ไม่ใช้) |
| ต้นทุนรวม `VC(v, P)` | น้ำมัน + ซ่อมบำรุง (WO ปิดในงวด) + ยาง (ติดตั้ง/หล่อดอก/ซ่อมในงวด) + ทางด่วน + ค่างวดลีสซิ่ง + ประกัน/พ.ร.บ./ภาษีรถ (เฉลี่ยรายเดือน) + ค่าใช้จ่ายรถอื่น — ทั้งหมดก่อน VAT; ไม่รวมค่าแรงคนขับ (ตัวเลือกเพิ่มได้) |
| ต้นทุน/กม. รายคัน | `VC(v, P) / km(v, P)` |
| ต้นทุน/กม. รายประเภทรถ | `Σ_v VC / Σ_v km` (ถ่วงน้ำหนัก ไม่ใช่ค่าเฉลี่ยของอัตรา) |
| อัตรากินน้ำมัน (กม./ลิตร) | วิธีเติมเต็มถึงเต็ม: ช่วง i ระหว่างการเติม "เต็มถัง" 2 ครั้งติดกัน `km_i = odo_end − odo_start`, `L_i = Σ ลิตรที่เติมหลังครั้งแรกจนถึงครั้งที่สองรวม`; ค่าของงวด = `Σ km_i / Σ L_i` เฉพาะช่วงที่ปิดในงวด (ต้องมี flag `isFullTank` ที่รายการเติม — 06) |
| อันดับน้ำมัน | เรียงภายในประเภทรถเดียวกัน; ผิดปกติเมื่อ `< median(ประเภท) × (1 − 15%)` [PROPOSED] หรือลดลง > 15% จากค่าเฉลี่ย 3 เดือนของคันเอง |
| Downtime % | `Σ ชั่วโมงที่รถไม่พร้อมใช้ (สถานะ ซ่อม/จอดซ่อม หรือ WO ที่ offRoad ตั้งแต่ offRoadAt ถึง returnedAt, ตัดเฉพาะส่วนในงวด) / ชั่วโมงทั้งหมดในงวด × 100` — ฐานชั่วโมง 24×7 [PROPOSED] [OPEN] RQ4; แยกสาเหตุ PM / ซ่อมเสีย / อุบัติเหตุ |
| PM ตรงเวลา % | `count(PM ที่ครบกำหนดในงวดและทำเสร็จตรงเวลา) / count(PM ที่ครบกำหนดในงวด) × 100`; ครบกำหนด = ตัวกระตุ้นที่ถึงก่อนระหว่างวันที่หรือเลขไมล์; ตรงเวลา = เสร็จ ≤ dueDate + 7 วัน หรือ ≤ dueKm + 1,000 กม. (ตามตัวกระตุ้นที่ถึงก่อน; ค่าผ่อนผันตั้งได้); ที่ยังไม่ทำเมื่อพ้นผ่อนผัน = ไม่ตรงเวลา |
| TCO รายคัน (ถึงวันที่ asOf) | ราคาซื้อ (หรือเงินดาวน์ + Σ ค่างวดลีสซิ่งที่จ่าย) + Σ ต้นทุนดำเนินงานตลอดอายุ (น้ำมัน ซ่อม ยาง ประกัน ภาษีรถ ค่าปรับที่บริษัทจ่าย) − มูลค่าขายต่อ (ถ้าจำหน่ายแล้ว); TCO/กม. = TCO / กม. ตลอดอายุ — ไม่รวมค่าเสื่อมแยก (กันนับซ้ำกับราคาซื้อ) [PROPOSED] [OPEN] RQ5 |
| ต้นทุนยาง/กม. รายเส้น | `(ราคาซื้อ + หล่อดอก + ซ่อม) / Σ กม. ที่วิ่งขณะติดตั้ง` (จากเลขไมล์ตอนติดตั้ง/ถอดทุกครั้ง); ต้นทุนยางของรถในงวด = Σ ค่ายางที่เกิดในงวด (ซื้อ/หล่อดอก/ซ่อม) — [OPEN] RQ7 |
| ค่าปรับต่อคนขับ | ต่อคนขับในงวด: จำนวนใบสั่ง, Σ ยอด, แยกประเภท (ขับเร็ว จอดห้าม น้ำหนักเกิน ฯลฯ), บริษัทจ่าย vs หักคนขับ, `ใบสั่งต่อ 10,000 กม.` = count / km ที่คนขับวิ่ง × 10,000 |

6–7. — event `fleet.fuel_anomaly_detected` (ใช้แจ้งเตือน/ข้อยกเว้น)

- **RPT-090** Excel: ค่าเงิน/ตัวเลขเป็น cell ตัวเลขจริง (ไม่ใช่ข้อความ) ทศนิยม 2 ตำแหน่ง; วันที่เป็น cell วันที่; แถวหัวมีชื่อรายงาน ตัวกรอง เวลาที่สร้าง ผู้สร้าง และ "ข้อมูล ณ"; คอลัมน์ตามที่ผู้ใช้เลือกแสดง
- **RPT-091** > 50,000 แถว → async job (`PENDING/COMPLETED/ERROR`) แจ้งเมื่อเสร็จ ลิงก์อายุ 7 วัน ต้อง login
